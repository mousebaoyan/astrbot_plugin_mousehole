# 回放实验

用导出的历史群消息离线跑一遍自动收录（[设计](design.md)第 8 节），调门槛、提示词和版块。实验在跑 AstrBot 的那台机器上做，那里有 OneJev、大模型和导出的聊天记录。

## 1. 要定的事

| 要定的 | 现在的值 | 怎么定 |
| --- | --- | --- |
| OneJev 的两个问题怎么问、门槛 | 0.3 | 第 5.1 节 |
| 一轮多少条、最多等多久 | 30 条、10 分钟 | 看一个问题被轮次切开的多不多，切开后更新得对不对 |
| 给多少上下文 | OneJev 10 条，大模型 20 条 | 看提问的前半句在上一轮时，能不能合上 |
| 大模型的提示词 | 设计第 8.3 节的规矩 | 第 5.2 节 |
| 不重复发帖 | 设计第 8.5 节 | 第 5.3 节 |
| 查重的语义门槛 | 0.5 | 第 5.3 节 |
| 跟进多少条 | 200 条 | 看回答离问题有多远，有多少落在 200 条以外 |
| 版块和标签 | 还没有 | 第 6 节 |

这些数和提示词可以直接改。要改设计第 8 节的规则（收什么、记在谁名下、正文怎么整理、要不要发帖），先问维护者。定下来的数写成 `_conf_schema.json` 的默认值，连同提示词在同一个提交里写回设计第 4 节和第 8 节。

## 2. 数据

聊天记录用 [QQChatExporter](https://github.com/shuakami/qq-chat-exporter) 导出，一个群一个 JSON 文件。维护者手里的一份是 3 天、约 6500 条。

文件和跑出来的结果里都有群友的 QQ 号、群名片和聊天原文：
- 放在仓库外面，或者仓库里的 `data/`、`replay-out/`，这两个目录不进 git；
- 提交信息、文档里不贴原文，只写统计数字；要举例就自己编一个。

用到的字段（示例的值是编的）：

```json
{
  "chatInfo": { "type": "group", "peerUid": "100200300", "selfUin": "20000" },
  "messages": [
    {
      "id": "7690000000000000002",
      "seq": "2500002",
      "timestamp": 1791500000000,
      "sender": { "uin": "10001", "name": "23-某校-鼠鼠" },
      "content": {
        "elements": [
          {
            "type": "reply",
            "data": { "referencedMessageId": "7690000000000000001", "senderUin": "10002" }
          },
          { "type": "at", "data": { "uin": "10002", "name": "24-某校-阿柒" } },
          { "type": "text", "data": { "text": " 看学校，有些可能是不好撤回" } }
        ]
      },
      "recalled": false,
      "system": false
    }
  ]
}
```

- `peerUid` 是群号，`selfUin` 是导出用的账号，当作 bot，它的消息按"bot 自己发的"去掉。
- `seq` 当消息 ID 用：群内唯一，是整数。`id` 太长，只用来对上引用。
- `timestamp` 是毫秒，`sender.name` 是群名片，只用在结果里给人看。
- `system` 为真的是进群、撤回之类的系统提示，跳过。撤回的消息在文件里已经没有原文，回放不测撤回。

`elements` 转成 OneBot 消息段，收录代码只认 OneBot 消息段：

| 导出的元素 | OneBot 消息段 |
| --- | --- |
| `text` | `text`，`{text}` |
| `at` | `at`，`{qq: uin, name}` |
| `reply` | `reply`，`{id: 被引用消息的 seq}`；`referencedMessageId` 是被引用消息的 `id`，为空或者文件里找不到的，当作没有引用 |
| `image`，`subType` 为 `sticker` | 表情包，`image`，`sub_type` 为 1 |
| `image`，`subType` 为 `photo` | 图片，`image`，`sub_type` 为 0；导出里的图片链接是本地相对路径，回放不下载 |
| `face`、`market_face` | `face`、`mface` |
| `file`、`forward`、`json` | `file`、`forward`、`json` |

不要用 `content.text` 判断命令：它把 QQ 表情写成了"/菜汪"这样的文字。

## 3. 回放工具

`tools/replay.py` 跑的是插件里同一份收录代码（`mousehole/archive.py`、`mousehole/judge.py`、`mousehole/similar.py`），只换掉外面：

| 插件里 | 回放时 |
| --- | --- |
| 收到的群消息 | 导出文件里的消息，转成 OneBot 消息段，按顺序喂进去 |
| 时间 | 消息的时间：一轮"等 10 分钟"按消息时间算，不真等 |
| 论坛 | 内存里的假论坛（`tools/fake_forum.py`，单元测试也用它）：记下发帖、回复和更新，答 `GET /bot/messages`；`GET /search/similar` 按标题和正文的字的二元组重合度找最像的 5 个；版块和标签从 `--boards` 读；图片不真的下载 |
| OneJev | 真的，`--onejev` 指定地址，默认 `http://127.0.0.1:8000` |
| 大模型、嵌入模型、OneJev | 和插件同一份客户端，从 `--config` 读插件的配置：地址、密钥、模型、结构化输出、思考模式都一样。每天的 token 上限不管 |
| 要调的数 | 门槛、一轮的大小、跟进多久、相似的门槛也从 `--config` 读，`--threshold` 可以临时改门槛 |

`--config` 用 AstrBot 存的插件配置文件 `data/config/astrbot_plugin_mousehole_config.json`，复制一份到 `data/` 再用；里面有密钥，不进 git。调数时改这份副本，定下来后改 `_conf_schema.json` 的默认值，再告诉维护者在插件配置里改。

收录代码只依赖三样东西：论坛的 httpx 客户端（回放时传接到假论坛的 `MockTransport`），一个"给系统提示词和提示词、返回文字和 token 用量"的函数，一个"给一批文字、返回向量"的函数。

```bash
uv run python -m tools.replay data/export.json --config data/config.json --boards data/boards.json --out replay-out/day1-a --until 2026-10-11
```

| 参数 | 作用 |
| --- | --- |
| `--boards FILE` | 版块和标签：`{"boards": [{"slug", "name", "description"}], "tags": [{"name", "kind"}]}`，字段同论坛 `GET /boards`、`GET /tags` 的返回；不给就是自由分类（第 6 节） |
| `--out DIR` | 结果放在哪 |
| `--from`、`--until` | 只跑这段时间的消息，`YYYY-MM-DD`，都含当天 |
| `--config FILE` | 插件的配置文件，见上 |
| `--rounds N` | 跑满 N 轮就停，照常写出结果；换了提示词或门槛，先跑几轮看效果和花费 |
| `--threshold X` | OneJev 的门槛，不给用配置里的；给 0 就每一轮都交给大模型，同时记下 OneJev 的分数（第 5.1 节） |
| `--no-onejev` | 不问 OneJev，每一轮都交给大模型；OneJev 不在线时调提示词用 |

OneJev 一次 10 秒左右，3 天的记录约 170 轮，跑一遍要半小时。它的结果缓存在 `replay-out/onejev-cache.jsonl`，以完整的请求体为键，只改大模型的提示词时重跑不用再等；改了 OneJev 的输入或问题自然就对不上，会重新问。

## 4. 结果

`--out` 目录下：

| 文件 | 内容 |
| --- | --- |
| `threads.md` | 本来会发的帖子，按发帖时间排：标题、版块、标签，每一层整理后的正文，下面列出它收进的原消息（时间、群名片、原文）；更新过的列出每一版，并进旧帖子的问题标出来 |
| `rounds.jsonl` | 每跑完一轮写一行，中途停掉也留着：消息范围和时间，OneJev 的两个分数和耗时，交没交给大模型、为什么，大模型的原始输出、token 和耗时，采纳和丢掉的项（带原因） |
| `summary.md` | 总数和折算到每天的数：消息、轮次、通过初筛的比例、大模型调用次数、token、OneJev 和大模型的总耗时，新帖、回答、更新、`same_as` 和查重并进旧帖的各多少，丢掉的项按原因分（其中"消息已经收过"单列）；疑似重复的帖子（第 5.3 节）；门槛为 0 时附第 5.1 节的门槛表 |
| `categories.md` | 只在自由分类时有：每个类别多少个问题，各举几个标题；分类是每个帖子再调一次大模型，这部分的 token 写在末尾，不算进 `summary.md` |

## 5. 怎么评

先用一天的消息调，最后再跑全部。每轮都交给大模型时，一天约 60 轮，三十几万 token。

### 5.1 初筛

1. 用 `--threshold 0` 跑一遍：每轮都交给大模型，同时记下 OneJev 的分数。大模型采纳了至少一项（新的一层或更新）的轮次，当作"该放过去的"。
2. 对 0.1 到 0.9 的门槛，算两样：
   - 漏掉的：该放过去的轮次里，分数低于门槛的比例；
   - 放过去的：所有轮次里，分数达到门槛的比例，它决定 token 花多少。
3. 选漏掉的在 5% 以内、放过去的最少的门槛。漏得多，先改 OneJev 的问法和 `state` 的写法，再看门槛。

### 5.2 整理

读 `threads.md`，至少看 30 个帖子；再从没收任何东西的轮次里，挑 30 个带问号或"吗""怎么""有没有"的看原文。逐条对这几类问题，记下每类有几个：

| 问题 | 例子 |
| --- | --- |
| 收错 | 闲聊、玩笑、反问、广告当成了提问 |
| 漏收 | 正经的问题或回答没收 |
| 记错人 | 一层里混进了别人的话 |
| 挂错 | 回答挂到了别的问题下面，或者回复错了楼层 |
| 改了意思 | 正文加了原文没有的信息，改了数字、学校，口气变了 |
| 拆错 | 一个问题拆成了两个帖子，两个问题并成了一个 |
| 补充没进去 | 提问的人后来说的背景没进主楼，回答的人补的话没进那一层 |
| 标题 | 太长、不像标题、没说清问什么 |
| 版块和标签 | 选得不对，或者该选的没选 |

改提示词，重跑同一天，对比这几类的数。"改了意思"和"记错人"是硬伤，要压到 0。

### 5.3 不重复发帖

最怕的是一个问题讨论了很多轮，bot 每轮都开一个新帖。逐个检查：
- 疑似重复：`summary.md` 列出两类帖子，一是和更早的帖子二元组重合度高的，二是开帖时作者已经有跟进中的问题的。逐对看是不是同一个问题，是的话看是哪一层（设计第 8.5 节）没拦住。
- 并进旧帖子的问题：是不是真的同一个问题，旧帖的回答能不能直接用。合错了比漏合更糟，回答会挂到别的问题下面。
- 找候选：对每一对确认是重复的，看旧帖子有没有进候选，是语义找到的、字面找到的，还是都没找到；以及它的语义相似度。据此定语义门槛，并看字面检索还有没有补上语义漏掉的，没有就提议去掉。
- "消息已经收过"被丢掉的项：多说明大模型在重复收上下文里的消息，要改提示词，即使代码拦住了。

重复的帖子要压到 0。

### 5.4 花费

按每天折算：大模型调用多少次、多少 token（输入、输出分开），OneJev 一共跑多久。对照设计第 8.3 节的估算。

## 6. 版块和标签

1. 不给 `--boards` 跑一遍：所有问题先放进一个"未分类"版块，跑完再让大模型给每个帖子写一个不超过 6 个字的类别和最多 5 个标签，结果在 `categories.md`。
2. 看 `categories.md`，把意思相同的类别合并，提出 6 到 10 个版块，盖住九成以上的问题。每个版块写名字、地址（英文小写，比如 `qa`）和一句说明。论坛已有的初始版块见鼠洞总体设计 §8.1，合适的直接用。
3. 提出 20 到 40 个标签，分话题、院校、方向三类（论坛的 `kind` 是 `topic`、`school`、`major`），只要出现得多的。
4. 写成 `data/boards.json`，用它重跑一遍，看版块和标签选得对不对。
5. 交给维护者在论坛后台建好。

## 7. 汇报

做完一轮实验，跟维护者说清楚：
- 定下来的数和提示词，为什么这么定；
- 第 5.1 节的门槛表，第 5.2 节每类问题的个数，有代表性的例子；
- 每天的花费；
- 版块和标签的提议。

代码和提示词的改动直接提交到 `main`；定下来的数和提示词同时写回设计第 8 节。
