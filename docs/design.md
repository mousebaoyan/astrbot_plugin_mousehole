# 鼠洞插件 · 设计

> 状态：都已经定了，代码写好了第一版，单元测试齐全，还没在 AstrBot 上跑过。接下来先装到 AstrBot 上联调（自动收录先关着，第 12 节），再跑回放调自动收录，然后建收录用的版块（第 11 节）、打开自动收录。第 8 节（自动收录）的门槛、轮次大小、提示词和版块用历史记录调，见[回放实验](replay.md)。论坛要配合的改动列在第 11 节。论坛一侧见鼠洞仓库的[总体设计](https://github.com/mousebaoyan/mousehole/blob/main/docs/design.md)和[接口](https://github.com/mousebaoyan/mousehole/blob/main/docs/api.md)；本文只写插件自己的部分，接口细节以论坛的文档为准。

## 1. 目标

AstrBot 插件，把鼠群的 QQ 群和鼠洞论坛连起来（论坛总体设计 §14 M9）。群友几乎感觉不到它，它只做这几件事：

- 登录入口：私聊 bot 登录论坛。
- 群成员同步到论坛。
- 自动收录：群里正经的提问（不限于保研）连同群友的回答，由大模型整理成论坛的帖子和回复，分好版块和标签（第 8 节）。
- 开奖结果发到群里。

论坛的提醒由论坛自己发邮件到 `QQ号@qq.com`，不经过插件（第 9 节）。

不做：
- 群里的命令：转存、"不给访客看"、参与抽奖、搜索，都到论坛上操作。
- 收录后发回执。
- 主动私聊，自动通过好友申请。
- LLM 审核。
- 二期的播报、群公告和精华同步。

## 2. 防风控

QQ 的风控会识别"像机器人"的账号，插件尽量让 bot 的操作和真人没有区别：

- 群消息和通知只被动接收。
- 读 NapCat 只读它的缓存，不让它为插件额外去 QQ 服务器拉数据。
- 不主动私聊别人，私聊只回复本人发来的消息（登录）。
- 回复（私聊登录、群里的"登录请私聊我"）前随机等 1–2 秒，不在收到消息的同一瞬间回。
- 主动发到群里的只有开奖结果。
- 发出的消息尽量不带链接，必须带的只有登录链接和开奖结果。

插件让 NapCat 做的事只有这些：

| 操作 | 会不会请求 QQ 服务器 | 什么时候 |
| --- | --- | --- |
| `get_group_member_list`、`get_group_info`，都不带 `no_cache` | 不会，读 NapCat 的缓存 | 每小时；有人进群时 |
| `get_stranger_info` 查个性签名 | 会 | 有人第一次登录论坛时 |
| 私聊回复登录 | 会 | 本人私聊 bot 时 |
| 发开奖结果 | 会 | 开奖时 |

- `get_group_member_list` 带 `no_cache: true` 时，NapCat 会在后台重新拉名单，却仍然先返回旧的缓存，所以插件从来不带。
- `get_group_member_info` 默认就强制刷新，还会多查一次这个人的资料，所以插件不用它。
- 自动收录只读收到的群消息，不调用 QQ 接口。

开奖结果排队发，间隔 3–6 秒随机。AstrBot 里有维护者其他插件共用的操作协调器（`platform_manager._qq_automation_guard_v1`）时改走它，和那些插件一起排队，共用账号的发送间隔和掉线后的冷却。

## 3. 运行环境

- AstrBot 4.26.2 以上、5.0 以下，Python 3.12 以上（这些版本的 AstrBot 本身就要求 3.12）。通过 aiocqhttp 反向 WebSocket 接 NapCat，接口按 NapCat 4.18 核对；只支持 aiocqhttp。
- 插件主动连接论坛（REST 和事件流），所在的机器能访问外网就行，论坛不反向连接插件。
- 自动收录还要：
  - [OneJev](https://github.com/OmniJev/OneJev) 服务做初筛。维护者家里的电脑上跑 4B 模型，一次判断约 10 秒，和 message_guard 插件共用。它连不上时收录暂停，不改用大模型（第 8.2 节）。
  - 一个大模型（整理）和一个嵌入模型（embedding，查重，第 8.5 节），都走 OpenAI 兼容接口。大模型现在用 ECNU 的 `ecnu-plus`；嵌入模型用 bge-m3，和 OneJev 跑在同一台电脑上（比如用 Ollama），也可以用 ECNU 的 `ecnu-embedding-small`。
  - 插件直接调这两个接口，不经过 AstrBot 的模型配置：AstrBot 的 `llm_generate` 会丢掉每次请求自带的参数，传不了结构化输出和思考模式。回放用的也是同一份客户端和同一份配置（[回放实验](replay.md)第 3 节）。
- 依赖只有 httpx 和 numpy，AstrBot 已经自带。
- 论坛的 token：管理员在后台的 bot 页创建，bot 的 QQ 号填机器人自己的，范围选 `read`、`act`、`sync`、`auth`、`events`。
- AstrBot 开了会话白名单的，要放行已同步的群，否则群消息和通知到不了插件。私聊不受白名单影响：白名单在所有插件之前检查，而且没法放行所有私聊，所以插件直接在 aiocqhttp 的客户端上订阅私聊消息（第 7 节）。
- 本机时间要准：论坛拒收比服务器时间晚 10 分钟以上的同步数据。

## 4. 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `forum_url` | `https://bbs.mousebaoyan.cn` | 论坛地址 |
| `token` | 空 | 论坛的 bot token，界面上遮住显示；空的插件什么都不做 |
| `platform_id` | 空 | 接了多个 aiocqhttp 时指定用哪个，只有一个时留空 |
| `sync_members` | 开 | 成员同步（第 6 节）。关掉后只读论坛关联了哪些群，不推成员 |
| `login` | 开 | 私聊登录（第 7 节）。关掉后 bot 不理"登录"和口令 |
| `push_bio` | 开 | 成员第一次登录时推 QQ 个性签名（第 6 节），要请求一次 QQ 服务器 |
| `lottery.enabled` | 开 | 开奖结果发到群里（第 9 节） |
| `lottery.groups` | 空 | 发到哪些群，空的发到主群 |
| `archive.enabled` | 关 | 自动收录（第 8 节）。回放调好、论坛上建好收录用的版块再打开 |
| `archive.groups` | 空 | 收录哪些群，空的是论坛上关联的所有群 |
| `archive.round_messages`、`archive.round_minutes` | 30、10 | 一轮最多几条、最多等几分钟（第 8.1 节） |
| `archive.follow_messages` | 200 | 跟进多少条消息（第 8.6 节） |
| `onejev.url`、`onejev.api_key`、`onejev.model` | `http://127.0.0.1:8000`、空、`jev-latest` | OneJev 服务 |
| `onejev.threshold` | 0.3 | 交给大模型的门槛（第 8.2 节） |
| `llm.base_url`、`llm.api_key`、`llm.model` | ECNU 的地址、空、`ecnu-plus` | 大模型，OpenAI 兼容接口 |
| `llm.structured_output` | `json_schema` | `json_schema` 按插件给的格式约束输出；`json_object` 只要求是 JSON；`off` 不传 |
| `llm.thinking`、`llm.reasoning_effort` | `enabled`、`low` | 思考模式和思考程度（ECNU 的 `thinking`、`reasoning_effort`）；`omit` 是不传，给不认这些参数的接口用 |
| `llm.temperature` | 0.2 | 只在不思考时传 |
| `llm.max_tokens`、`llm.timeout_seconds` | 8192、180 | 每次最多输出多少 token（含思考）、最多等几秒 |
| `llm.tokens_per_day` | 100 万 | 每天最多用多少 token，用完当天不再整理；0 不限 |
| `embedding.base_url`、`embedding.api_key`、`embedding.model` | 本机 Ollama、空、`bge-m3` | 嵌入模型，OpenAI 兼容接口；换了地址或模型，向量索引重建 |
| `embedding.min_similarity` | 0.5 | 语义相似的门槛（第 8.5 节） |

同步哪些群在论坛后台关联，插件不另外配。打开了收录、却没填好 OneJev、大模型或嵌入模型时，插件记一条错误，其他功能照常。

回放要调的数（门槛、一轮的大小、跟进多久、相似的门槛）做成配置，调好后改默认值，不用改代码。其他频率和间隔写成常量，见下面各节。

## 5. 结构

```text
NapCat ⇄ AstrBot（aiocqhttp）
           └ 鼠洞插件
               ├ 群消息 → 自动收录（含撤回）
               ├ 私聊 → 登录
               ├ 群通知 → 成员增量
               ├ 每小时 → 成员全量、群资料
               └ 事件流 → 开奖结果、个性签名
                     ⇅ REST、SSE（Bearer token，X-Act-As）
                  鼠洞论坛
自动收录另外调用 OneJev、大模型和嵌入模型（OpenAI 兼容接口）
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | AstrBot 入口：注册监听，启动、停止后台任务 |
| `mousehole/forum.py` | 论坛接口：请求头、gzip，错误转成 `ForumError(code, message)` |
| `mousehole/qq.py` | 调用 NapCat；回复前的延迟，主动发的消息排队 |
| `mousehole/sync.py` | 成员同步 |
| `mousehole/login.py` | 私聊登录 |
| `mousehole/archive.py` | 自动收录：消息和分轮、跟进、发帖和更新、撤回 |
| `mousehole/judge.py` | 自动收录用的模型：OneJev 初筛，大模型的提示词和输出的检查 |
| `mousehole/similar.py` | 查重：帖子的向量索引，找和新提问最像的帖子 |
| `mousehole/events.py` | 事件流，以及它触发的开奖结果、个性签名和向量索引的更新 |
| `tools/fake_forum.py` | 内存里的假论坛，单元测试和回放用 |
| `tools/replay.py` | 用导出的历史群消息离线跑自动收录（[回放实验](replay.md)） |

论坛是唯一的数据源，插件几乎不存东西：数据目录（`data/plugin_data/astrbot_plugin_mousehole/`）里只有 `state.json`，记事件流的游标；和 `threads.npz`，帖子的向量索引，丢了可以从论坛重建（第 8.5 节）。谁在哪个群、群消息、跟进中的问题都只放在内存里。

## 6. 成员同步

| 内容 | 做法 | 时机 |
| --- | --- | --- |
| 同步哪些群 | `GET /bot/groups`：后台关联且启用的群，主群在前 | 启动时、每小时 |
| 完整成员名单 | `get_group_member_list` 的结果原样转给 `PUT /bot/groups/{群号}/members`，带全部字段，gzip 压缩 | 启动后，之后每小时 |
| 群名、人数 | `get_group_info` → `PUT /bot/groups/{群号}/info` | 和全量一起 |
| 进群、退群、管理员、群名片、专属头衔 | QQ 通知转成增量，`PATCH /bot/groups/{群号}/members` | 收到通知时 |

NapCat 自己维护成员缓存，插件只读它（第 2 节）。不管有没有插件，NapCat 都会：
- 启动时拉一遍所有群的名单；
- 有人进群、退群、管理员变动时，先重新拉这个群的名单再发通知；
- 有人改了群名片，等他下次发言时更新。

所以缓存够新，全量每小时读一次就够了。

- 进群时，从缓存的名单里取出这个人的记录一起推，账号一建好就有名字。
- 缓存里的最后发言时间只在 NapCat 重新拉名单时更新。插件本来就在看群消息，全量时用看到的最近发言时间，替换缓存里更早的。
- `observed_at`：全量用读缓存的时间，增量用通知里的 `time`。
- 通知按论坛接口 §4.2 的表转换；专属头衔是 `notify` 通知，`sub_type` 为 `title`。
- bot 自己被踢（`kick_me`）或者群解散（`disband`）不推送，只记日志，由管理员在后台停用这个群。
- 全量被骤减保护拦下（`held`）时记一条警告。

头像不经过插件，论坛每天自己从 QQ 头像接口拉。个性签名由插件推：收到 `member.activated` 时，用 `get_stranger_info` 查 `long_nick`，推给 `PUT /bot/users/qq:{QQ号}/bio`。

## 7. 登录

私聊 bot，以"登录"开头的消息：

| 发送 | 做什么 |
| --- | --- |
| `登录`、`登录链接` | `POST /bot/auth/links`，回复一次性登录链接，10 分钟内有效，只能用一次 |
| `登录 482913`，或者只发 6 位口令 | `POST /bot/auth/code/confirm`，回复"已在 Chrome · macOS 登录鼠洞。不是你本人在登录的话，到鼠洞设置页的登录设备里让它下线。" |

- "登录"后面跟 6 位数字就是口令，其他都发链接。
- 私聊不走 AstrBot 的管线：插件在 aiocqhttp 的客户端上订阅 `message.private`，插件比平台先加载时（AstrBot 启动）在 `on_platform_loaded` 里订阅，停止时退订。管线里收到的登录私聊只 `stop_event`，免得 AstrBot 的大模型也回一句。
- 以发送者的身份调用（`X-Act-As` 和 `X-Operator` 都是发送者）。
- 群里 @bot 说"登录…"时，只回一句"登录请私聊我"。不 @ 的群消息不理会，群友聊天里说到"登录"很常见。
- 论坛返回的错误 `message` 本来就是给人看的，直接回复。几种常见的换成更具体的说法：

  | 错误码 | 回复 |
  | --- | --- |
  | `unknown_member` | 论坛还没同步到你，进群后稍等几分钟再试 |
  | `member_frozen` | 你已经不在鼠群里了 |
  | `login_code_invalid` | 口令不对或者过期了，刷新网页拿个新的 |

- 论坛连不上时回复"鼠洞暂时连不上，稍后再试"。
- 处理完停止事件传播，不让大模型再回。

## 8. 自动收录

群里正经的提问自动存成论坛的帖子，群友的回答存成回复：
- 收什么：在请教知识、经验、信息或建议，别人能回答、以后的人也可能会查的，都收，不限于保研，比如"大家怎么用 GPT 辅助科研"。
- 没人回答的也收：论坛上的人看到了可以回答，补上 QQ 群容易把问题刷过去的短处。
- 一个问题、一个回答常常分好几条发。大模型把同一个人的几条整理成一层：提问的整理成主楼，写清问题和背景；回答的整理成一层回复。后来补充的，更新进原来那一层。
- 一个问题只开一个帖子：讨论了很多轮、隔一阵又有人问，都并进已有的帖子（第 8.5 节）。
- 版块和标签由大模型在收录时选好，版块默认都公开。
- 都记在本人名下，论坛上标"整理自群聊"。bot 不在群里说话，群友察觉不到。
- 收录的内容不触发论坛的任何提醒，只有在论坛上发的回复才提醒（第 9 节）。

### 8.1 消息和分轮

每个群的消息按到达顺序编号，放在内存里。规则先去掉这些，它们不进轮次，也不给模型看：
- bot 自己发的；
- 命令：文字以 AstrBot 的唤醒前缀开头的；
- 只有表情的：QQ 表情（`face`）、商城表情（`mface`）、表情包（`image` 的 `sub_type` 为 1）。

短消息照收："不是""可以"这种两三个字的，常常就是回答；几条短消息合起来，才是一个完整的问题。

剩下的消息攒成一轮：满 30 条，或者第一条之后过了 10 分钟。各群分开攒；所有群的轮次排成一队，一次处理一轮，帖子都发完了才处理下一轮（第 8.5 节），OneJev 和大模型同时只有一个请求。

给模型看的消息每条一行：编号、作者代号、引用了哪条、文字。

```text
#1203 U4 ↩#1201 看学校，有些可能是不好撤回
```

- 作者写成 U1、U2……，每个群一套，插件运行期间不变。不给模型看 QQ 号和群名片。
- @ 某人写成 @U3；图片写成"[图片]"；文件、合并转发、卡片写成"[文件]""[聊天记录]""[卡片]"。
- 引用的消息不在内存里时写"↩更早的消息"。
- 已经收进论坛的消息后面标上它所在的那一层，比如"〔已收：Q2〕"。

### 8.2 OneJev 初筛

每轮发一次 `/v1/systemone`（`debias=1`）：
- `state`：这一轮的消息、前面 10 条作上下文、跟进中的问题的标题。
- 问题都是 `noul`：
  - `question`：这一轮里有没有人在正经地提问或求助；
  - `answer`：有跟进中的问题时才问，这一轮里有没有消息在回答、补充或讨论这些问题。
- 任一个超过门槛就交给大模型。门槛先定 0.3，偏低，宁可多放过去；用历史记录调。

这一轮里有消息引用了跟进中的问题或者已收录的消息时，不问 OneJev，直接交给大模型。

OneJev 连不上时，这一轮等着，每分钟重试一次，后面的轮次排在它后面；不改用大模型，免得 token 花得太多。断开和恢复时各记一条日志。OneJev 拒收这一轮的输入（`413`、`422`）时跳过这一轮。插件重启时，没处理完的轮次丢掉。

### 8.3 大模型整理

通过初筛的轮次，调用一次大模型（`llm`）。这一次做完所有事：
- 认出新的提问，起标题，选版块和标签；
- 把同一个人的几条整理成一层；
- 判断回答的是哪个问题；
- 把后来补充的内容更新进已有的那一层。

输入：
- 跟进中的问题（第 8.6 节）：编号 Q1、Q2……，标题，主楼的正文，已有的回答（编号 A1、A2……，作者代号，正文）。每一层都带上它收进的原消息，更新时从原消息重新整理。
- 上下文：这一轮前面的 20 条。没收过的可以和这一轮的消息合成一层，比如提问的前半句在上一轮。
- 这一轮的消息。
- 论坛上成员能发帖的版块（`GET /boards` 的 slug、名字、说明）和已有的标签（`GET /tags`）。插件启动时取，之后每小时更新。

输出 JSON：

```json
{
  "new": [
    {
      "ref": "N1",
      "type": "question",
      "messages": [1201, 1204],
      "title": "预推免的第一批和第二批能都报吗",
      "body": "常说的预推免第一批、第二批，是一个人只能报其中一批吗？",
      "board": "qa",
      "tags": ["预推免"],
      "same_as": null
    },
    {
      "ref": "N2",
      "type": "answer",
      "question": "N1",
      "messages": [1203, 1207],
      "body": "看学校，有些学校报了以后不好撤回。",
      "reply_to": null
    }
  ],
  "edit": [
    { "post": "Q1", "messages": [1210], "title": null, "body": "……整理后的完整正文" }
  ]
}
```

- `new` 是新的一层：提问开新帖子，回答回复在问题所在的帖子里。`question` 填跟进中的问题（Q1）或这一轮新的提问（N1）。`reply_to` 填它回复的那一层，回复的是问题本身时为空。
- `edit` 是更新已有的一层：`messages` 是新补充的消息，`body` 是用这一层原来的消息加上新补充的重新整理出的完整正文，`title` 只在主楼、需要改时填。每次都从原消息整理，不在上一版正文上改，大模型写偏了的地方不会一版版累积下去。
- 一层只收一个人的消息，每条消息只收进一层。

开了结构化输出（`llm.structured_output` 为 `json_schema`）时，请求带上输出格式的 JSON Schema（`judge.py` 的 `ORGANIZE_SCHEMA`），ECNU 用受约束的解码保证输出一定是这个形状；内容对不对仍由下面的检查管。

规矩写在系统提示词里：
- 提问要自己能看懂、别人能回答。只有接着前文才看得懂的追问，算对应问题的回答，类型是 `answer`。附和、道谢、闲聊、玩笑、反问都不收。
- 整理正文：
  - 只用本人说过的内容，不加原文没有的信息，不替他下结论，人称和口气保持原样；
  - 把碎句连成通顺的话，补上标点，去掉表情、语气词和跟问题无关的话；
  - 提问的人在回答别人追问时说的情况，比如"rank 前 10%"，写进主楼；
  - 学校、专业、数字、链接、缩写照抄；
  - 正文是纯文字，不用 Markdown，不写作者代号和 @。
- 标题不超过 30 个字，像论坛的帖子标题，说清楚问的是什么。
- 版块只从给的里选。标签只从已有的里选，最多 5 个，没有合适的就不选。
- 跟进中的问题：接着讨论、追问、补充它的，是回答或更新，不是新的提问；提问的人把没人回的问题再问一遍，比如"有人知道吗"或者换个说法，是更新原来的主楼。
- `same_as`：别人问了和跟进中的问题、或者这一轮另一个新提问同样的问题时，填它的编号（Q1 或 N1，第 8.5 节）。

插件检查输出：编号和消息都要存在，已经收过的消息去掉（第 8.5 节），`edit` 至少要有一条新消息，同一层的消息要是同一个人的，版块要在列表里，标签只留已有的，标题截到 30 个字。不合格的那一项丢掉、记日志；整个不是 JSON 的，这一轮作废，记一条警告。

每轮的输入大约 4–6k token，输出几百。按一个群一天约 1700 条有效消息、60 轮、一半通过初筛估算，一天约 20 万 token。

### 8.4 发帖和更新

| 输出 | 调用 | `X-Act-As` |
| --- | --- | --- |
| 新的提问 | `POST /threads`：类型是问答（`question`），标题、版块、标签用大模型给的 | 提问的人 |
| 新的回答 | `POST /threads/{帖子 ID}/posts`，`reply_to_id` 是它回复的那一层 | 回答的人 |
| 更新 | `PATCH /posts/{楼层 ID}`；改标题时再 `PATCH /threads/{帖子 ID}` | 那一层的作者 |

- 内容用 `content.onebot`：整理好的正文是一个文字段，后面按原来的顺序接上这些消息里的图片（不含表情包）。每张图片第一次用到时，插件先用 `POST /uploads/fetch` 转存到论坛（存在论坛服务器的数据卷里，和网页上传的图片一样）、记下论坛上的地址，之后发帖和更新都给这个地址：QQ 的图片链接几小时就过期，更新可能在很久以后。每轮最多攒 10 分钟，赶得上链接过期之前转存。
- `source` 是这一层收进的全部消息：`{ chat_type: "group", chat_id: 群号, message_ids: [...] }`，论坛用它查某条消息属于哪一层（`GET /bot/messages`）。更新时带上完整的新列表。
- 本人在论坛上改过这一层，就不再更新它：插件记下自己最后一次写入后的 `edited_at`，更新前对一下，不一样就跳过，记日志。
- 都不带 `X-Operator`，因为自动收录没有操作人。论坛拒绝以这个人的身份发（比如他关了"允许代发"，`403 proxy_disabled`）时，插件跳过这一层；提问的人被拒绝时，整个问题连同回答都不收。
- `Idempotency-Key` 是 `qq-{群号}-{第一条消息 ID}-thread` 或 `qq-{群号}-{第一条消息 ID}-post`。返回 `409 source_exists`，说明已经收过（比如插件中途重启），用返回的 `thread_id` 和 `post_id` 接着跟进。

### 8.5 不重复发帖

一个问题常常讨论很多轮，每轮都调一次大模型；同一个问题也常有人隔一阵再问。大模型每次写出的文字都不一样，所以判断收没收过、发没发过，只看消息编号和帖子编号，从不比较它写的文字。下面四层保证一个问题只开一个帖子、一条消息只收一次。

1. **一条消息只收一次**：大模型的输出里，每一层写的是它收进的消息编号（`messages`），不是原文。插件记着每个编号收进了哪一层，输出里已经收过的编号直接去掉，去掉后一层里没有消息了，这一项就丢掉，都记日志。论坛那边一条消息也只能属于一层，重复收会返回 `409 source_exists`。所以同一条消息不管大模型这次怎么写，都不会再发一遍。
2. **没有新消息就不改**：`edit` 至少要带一条新消息，否则丢掉，已经发出去的正文不会因为大模型换了个写法来回改。
3. **跟进中的问题每轮都给大模型**，并且一轮的帖子和回复都发完、记下，才处理下一轮，所以下一轮一定能看到上一轮开的帖子。接着讨论的写成回答或更新，同一个人再问一遍的更新原来的主楼，别人问了同样的问题填 `same_as`（第 8.3 节的规矩）。请求超时重试时带同一个幂等键，论坛只建一次。
4. **开新帖前查重**：大模型给出新的提问时，先找最像的帖子当候选，再调用一次大模型判断。它兜住第 3 层漏掉的，也管跟进不到的：问题过了 200 条又被问起，插件重启后跟进的问题丢了，隔几天又有人问。

前两层由代码保证，后两层要判断意思，靠大模型；第 4 层的候选找不找得全，决定了它能兜住多少。

#### 找候选

同一个问题换个说法很常见（"拿了优营不去会怎样"和"夏令营 offer 能鸽吗"），只按字面找会漏，所以两种一起用：
- **语义**：插件用嵌入模型（`embedding`）给论坛上每个帖子的标题和主楼开头算向量，存在 `threads.npz`，跟着事件流更新（新帖、主楼改了、帖子删了）。启动时没有索引或者换了模型，就从论坛分页取回全部帖子重建。新提问的标题加正文也算一个向量，取余弦相似度最高的 5 个。帖子上万个也只是几十 MB，直接用 numpy 逐个算，不用向量数据库。
- **字面**：论坛的 `GET /search/similar`，取最像的 5 个。它把中文切成相邻两个字，任何一个对上就算，按对上的密度排序，能补上学校名、缩写这类向量不一定分得清的。

两边合起来去掉重复，最多 10 个；语义相似度低于门槛（先定 0.5，用回放调）、字面也没对上的不算。没有候选就直接发帖。

#### 判断

有候选时调用一次大模型：新问题，和每个候选的标题、版块、日期、回复数、主楼开头 100 个字，问哪个和它是同一件事、旧帖子的回答能不能直接回答它。
- 问的是自己的情况（"我这个条件能去哪"），不算和别人重复；问的是不同年份的事，比如今年和去年的夏令营，也不算。
- 每次一两千 token，一天几十次。

判为重复的不开新帖：这个提问作为一层回复发在已有的帖子里（`X-Act-As` 是提问的人），之后的回答都回复这一层。跟进时，这个问题就指向这一层。

### 8.6 跟进多久

- 不按时间算，按群里后来又有多少条消息算：问题的最后一条相关消息之后，群里又过了 200 条消息，就不再跟进。到那时问题早就被刷上去了，很难再有人回答。
- 群很安静时，问题可以跟进很久。
- 不再跟进以后，有人引用了已收录的消息，这一轮不问 OneJev，直接交给大模型。插件用 `GET /bot/messages` 查到这条消息在哪个帖子，从论坛取回帖子的主楼和最近的回答，重新跟进这个问题。取回的楼层只给模型作参考，不再更新。
- 跟进中的问题只在内存里，插件重启就丢了；已经发出的帖子，靠引用还能接上。

### 8.7 撤回

群友撤回自己的消息（`group_recall` 里撤回的人就是发送者）：
- 还没处理的：从这一轮里去掉。
- 已经收进某一层的，用 `GET /bot/messages` 查到是哪一层：
  - 这一层的其他消息都还在内存里：让大模型用剩下的几条重新整理正文，更新这一层，`source` 里去掉这一条。
  - 这一层只有这一条，或者其他消息已经不在内存里：以本人身份删掉这一层。是主楼就删整个帖子；帖子已经有人回复的，论坛不让删，就留着。

QQ 群里普通成员只能撤回自己 2 分钟内的消息，所以一般都是前一种；后一种只有管理员撤回自己很早的消息时才会遇到。管理员撤回别人的消息，插件不跟着处理。

### 8.8 以后再说

- 图片给大模型看：现在大模型只看到"[图片]"，只有截图没有文字的提问可能认不出来。
- 合并转发、文件和语音，按论坛的规则显示成"[聊天记录]"等，不展开。

## 10. 事件流

订阅这几种：
- `member.activated`、`lottery.drawn`：个性签名和开奖结果；
- `thread.created`、`post.updated`、`post.deleted`：更新查重用的向量索引（第 8.5 节）。新帖取回主楼开头算向量；主楼改了（`floor` 为 1）用事件里的标题和正文重算；主楼删了就从索引里去掉。改标题没有事件，插件自己改的标题当场重算，别人改的等主楼再改时才跟上。

- 先用 `GET /bot/events/batch` 把游标之后的事件补完，再连 `GET /bot/events`（SSE，带 `Last-Event-ID`）收新的。
- 补发时看得到事件的时间。超过 12 小时的开奖不再发到群里，只往前推游标，免得插件停了一天，一开机就发一堆过时的结果。
- 每处理完一个事件，把游标存进 `state.json`。
- 游标过期（`410 cursor_expired`）时从 `latest_id` 重新开始，记一条警告。
- 第一次启动没有游标，从当前最新的事件开始。
- 断线后隔 1、2、5、10、30 秒重连，之后每 60 秒一次，每次都先补发。
