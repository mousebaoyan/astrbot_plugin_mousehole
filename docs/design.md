# 鼠洞插件 · 设计

> 状态：草案。除第 8 节（自动收录）的细节外都已经定了，可以照着实现；待定的问题列在第 14 节。论坛一侧见鼠洞仓库的[总体设计](https://github.com/mousebaoyan/mousehole/blob/main/docs/design.md)和[接口](https://github.com/mousebaoyan/mousehole/blob/main/docs/api.md)；本文只写插件自己的部分，接口细节以论坛的文档为准。

## 1. 目标

AstrBot 插件，把鼠群的 QQ 群和鼠洞论坛连起来（论坛总体设计 §14 M9）。群友几乎感觉不到它，它只做这几件事：

- 登录入口：私聊 bot 登录论坛。
- 群成员同步到论坛。
- 自动收录：群里正经的提问（不限于保研），连同群友的回答，自动存成论坛的帖子和回复，由大模型分好版块和标签（第 8 节）。
- 开奖结果发到群里。

论坛的提醒由论坛自己发邮件到 `QQ号@qq.com`，不经过插件（第 9 节）。

不做：
- 群里的命令：转存、"不给访客看"、参与抽奖、搜索，都到论坛上操作。
- 收录后发回执。
- 主动私聊，自动通过好友申请。
- LLM 审核。
- 二期的播报、群公告和精华同步。

## 2. 防风控

QQ 的风控会识别"像机器人"的账号，插件尽量让 bot 的操作和真人没有区别：

- 群消息和通知只被动接收。
- 读 NapCat 只读它的缓存，不让它为插件额外去 QQ 服务器拉数据。
- 不主动私聊别人，私聊只回复本人发来的消息（登录）。
- 主动发到群里的只有开奖结果。
- 发出的消息尽量不带链接，必须带的只有登录链接和开奖结果。

插件让 NapCat 做的事只有这些：

| 操作 | 会不会请求 QQ 服务器 | 什么时候 |
| --- | --- | --- |
| `get_group_member_list`、`get_group_info`，都不带 `no_cache` | 不会，读 NapCat 的缓存 | 每小时；有人进群时 |
| `get_stranger_info` 查个性签名 | 会 | 有人第一次登录论坛时 |
| 私聊回复登录 | 会 | 本人私聊 bot 时 |
| 发开奖结果 | 会 | 开奖时 |

- `get_group_member_list` 带 `no_cache: true` 时，NapCat 会在后台重新拉名单，却仍然先返回旧的缓存，所以插件从来不带。
- `get_group_member_info` 默认就强制刷新，还会多查一次这个人的资料，所以插件不用它。
- 自动收录只读收到的群消息，不调用 QQ 接口。

开奖结果排队发，间隔 3–6 秒随机。AstrBot 里有维护者其他插件共用的操作协调器（`platform_manager._qq_automation_guard_v1`）时改走它，和那些插件一起排队，共用账号的发送间隔和掉线后的冷却。

## 3. 运行环境

- AstrBot 4.26.2 以上、5.0 以下，Python 3.12 以上（这些版本的 AstrBot 本身就要求 3.12）。通过 aiocqhttp 反向 WebSocket 接 NapCat，接口按 NapCat 4.18 核对；只支持 aiocqhttp。
- 插件主动连接论坛（REST 和事件流），所在的机器能访问外网就行，论坛不反向连接插件。
- 自动收录还要：
  - [OneJev](https://github.com/OmniJev/OneJev) 服务做初筛。维护者家里的电脑上跑 4B 模型，一次判断约 10 秒，和 message_guard 插件共用。
  - AstrBot 里配好的一个大模型。
- 依赖只有 httpx，AstrBot 已经自带。
- 论坛的 token：管理员在后台的 bot 页创建，bot 的 QQ 号填机器人自己的，范围选 `read`、`act`、`sync`、`auth`、`events`。
- AstrBot 开了会话白名单的，要放行已同步的群和私聊。
- 本机时间要准：论坛拒收比服务器时间晚 10 分钟以上的同步数据。

## 4. 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `forum_url` | `https://bbs.mousebaoyan.cn` | 论坛地址 |
| `token` | 空 | 论坛的 bot token，界面上遮住显示 |
| `platform_id` | 空 | 接了多个 aiocqhttp 时指定用哪个，只有一个时留空 |
| `lottery_groups` | 空 | 开奖结果发到哪些群，空的发到主群 |
| `onejev_url` | `http://127.0.0.1:8000` | OneJev 服务的根地址；空的不做初筛，每一轮都交给大模型 |
| `llm_provider` | 空 | 自动收录用的大模型，从 AstrBot 配好的里选；空的用 AstrBot 的默认模型 |

同步哪些群在论坛后台关联，插件不另外配；收录也只在这些群里做。频率、门槛、间隔都写成常量，见下面各节。

## 5. 结构

```text
NapCat ⇄ AstrBot（aiocqhttp）
           └ 鼠洞插件
               ├ 群消息 → 自动收录、撤回
               ├ 私聊 → 登录
               ├ 群通知 → 成员增量
               ├ 每小时 → 成员全量、群资料
               └ 事件流 → 开奖结果、个性签名
                     ⇅ REST、SSE（Bearer token，X-Act-As）
                  鼠洞论坛
自动收录另外调用 OneJev 和 AstrBot 里的大模型
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | AstrBot 入口：注册监听，启动、停止后台任务 |
| `mousehole/forum.py` | 论坛接口：请求头、gzip，错误转成 `ForumError(code, message)` |
| `mousehole/qq.py` | 调用 NapCat；主动发的消息排队 |
| `mousehole/sync.py` | 成员同步 |
| `mousehole/login.py` | 私聊登录 |
| `mousehole/archive.py` | 自动收录：分轮、初筛、精判、跟进、发帖 |
| `mousehole/events.py` | 事件流，以及它触发的开奖结果和个性签名 |
| `tools/replay.py` | 用历史群消息跑一遍自动收录，输出本来会发的帖子（第 8.5 节） |

论坛是唯一的数据源，插件几乎不存东西：数据目录（`data/plugin_data/astrbot_plugin_mousehole/`）里只有 `state.json`，记事件流的游标。谁在哪个群、群消息、跟进中的问题都只放在内存里。

## 6. 成员同步

| 内容 | 做法 | 时机 |
| --- | --- | --- |
| 同步哪些群 | `GET /bot/groups`：后台关联且启用的群，主群在前 | 启动时、每小时 |
| 完整成员名单 | `get_group_member_list` 的结果原样转给 `PUT /bot/groups/{群号}/members`，带全部字段，gzip 压缩 | 启动后，之后每小时 |
| 群名、人数 | `get_group_info` → `PUT /bot/groups/{群号}/info` | 和全量一起 |
| 进群、退群、管理员、群名片、专属头衔 | QQ 通知转成增量，`PATCH /bot/groups/{群号}/members` | 收到通知时 |

NapCat 自己维护成员缓存，插件只读它（第 2 节）。不管有没有插件，NapCat 都会：
- 启动时拉一遍所有群的名单；
- 有人进群、退群、管理员变动时，先重新拉这个群的名单再发通知；
- 有人改了群名片，等他下次发言时更新。

所以缓存够新，全量每小时读一次就够了。

- 进群时，从缓存的名单里取出这个人的记录一起推，账号一建好就有名字。
- 缓存里的最后发言时间只在 NapCat 重新拉名单时更新。插件本来就在看群消息，全量时用看到的最近发言时间，替换缓存里更早的。
- `observed_at`：全量用读缓存的时间，增量用通知里的 `time`。
- 通知按论坛接口 §4.2 的表转换；专属头衔是 `notify` 通知，`sub_type` 为 `title`。
- bot 自己被踢（`kick_me`）或者群解散（`disband`）不推送，只记日志，由管理员在后台停用这个群。
- 全量被骤减保护拦下（`held`）时记一条警告。

头像不经过插件，论坛每天自己从 QQ 头像接口拉。个性签名由插件推：收到 `member.activated` 时，用 `get_stranger_info` 查 `long_nick`，推给 `PUT /bot/users/qq:{QQ号}/bio`。

## 7. 登录

私聊 bot，以"登录"开头的消息：

| 发送 | 做什么 |
| --- | --- |
| `登录`、`登录链接` | `POST /bot/auth/links`，回复一次性登录链接，10 分钟内有效，只能用一次 |
| `登录 482913`，或者只发 6 位口令 | `POST /bot/auth/code/confirm`，回复"已在 Chrome · macOS 登录鼠洞。不是你本人在登录的话，到鼠洞设置页的登录设备里让它下线。" |

- "登录"后面跟 6 位数字就是口令，其他都发链接。
- 以发送者的身份调用（`X-Act-As` 和 `X-Operator` 都是发送者）。
- 群里 @bot 说"登录…"时，只回一句"登录请私聊我"。不 @ 的群消息不理会，群友聊天里说到"登录"很常见。
- 论坛返回的错误 `message` 本来就是给人看的，直接回复。几种常见的换成更具体的说法：

  | 错误码 | 回复 |
  | --- | --- |
  | `unknown_member` | 论坛还没同步到你，进群后稍等几分钟再试 |
  | `member_frozen` | 你已经不在鼠群里了 |
  | `login_code_invalid` | 口令不对或者过期了，刷新网页拿个新的 |

- 论坛连不上时回复"鼠洞暂时连不上，稍后再试"。
- 处理完停止事件传播，不让大模型再回。

## 8. 自动收录

群里正经的提问自动存成论坛的帖子，群友的相关回答存成回复：
- 不限于保研。只要是在请教知识、经验、信息或建议，别人能回答、以后的人也可能会查，就收。比如"大家怎么用 GPT 辅助科研"。
- 没人回答的也收：论坛上的人看到了可以回答，补上 QQ 群容易把问题刷过去的短处。
- 版块和标签由大模型在收录时一起选好，版块默认都公开。
- 都记在本人名下，论坛上标"来自群聊"；bot 不在群里说话，群友察觉不到。
- 收录的内容不触发论坛的任何提醒，只有在论坛上发的回复才提醒（第 12 节）。

### 8.1 分轮和三层判断

每个群的消息按到达顺序编号，放在内存里，只留最近的。规则筛过的新消息攒成一轮：满 30 条，或者第一条之后过了 10 分钟，就处理这一轮。

| 层 | 花费 | 做什么 |
| --- | --- | --- |
| 规则 | 无 | 去掉 bot 自己的、命令、只有表情或图片的、太短的（不到 4 个字） |
| OneJev 初筛 | 每轮一次，约 10 秒 | 这一轮值不值得交给大模型 |
| 大模型精判 | 通过初筛的轮次，每轮一次 | 认出提问，起标题、选版块和标签；判断回答的是哪个问题 |

**OneJev 初筛**：一轮发一次 `/v1/systemone`，`state` 是这一轮的消息和跟进中的问题，问一到两个 `noul`：
- 这一轮里有没有正经的提问；
- 有跟进中的问题时，有没有在回答或讨论它们的消息。

任一个超过门槛就交给大模型，门槛偏低，宁可多放过去。OneJev 连不上时，这一轮直接交给大模型，记一条警告。

**大模型精判**：一轮调用一次 `llm_provider`。
- 输入：
  - 跟进中的问题（编号、标题、原文）；
  - 这一轮的消息和前面几条作上下文，每条是编号、作者代号、文字、引用了哪条；
  - 论坛上成员能发帖的版块（名字和说明，`GET /boards`）和已有的标签（`GET /tags`）。
- 要它回 JSON：
  - 新的提问：哪条消息，标题（不超过 30 个字），版块，最多 5 个标签；
  - 回答：哪条消息，回答的是哪个问题，可以是跟进中的，也可以是这一轮里新的。
- 只有前文才看得懂的追问不算新的提问，算对应问题的讨论；附和、道谢、闲聊都不收。
- 作者写成 U1、U2，不给模型看 QQ 号和群名片。
- 一轮大约两三千 token。

引用了跟进中的问题或者已收录消息的，直接算对应问题的回答，不用模型判断。

### 8.2 发帖

- 新的提问：`POST /threads`。
  - 类型是问答（`question`），版块、标签和标题用大模型选的。
  - `content.onebot` 是原消息段，`source` 是原消息，`X-Act-As` 是提问的人。
- 回答：`POST /threads/{帖子 ID}/posts`，`X-Act-As` 是回答的人。原消息引用了帖子里某一条的，论坛自动记成回复那一层。
- 都不带 `X-Operator`，因为自动收录没有操作人。
  - 关了"允许代发"的人，论坛会拒绝（`403 proxy_disabled`），插件就跳过这条。
  - 提问的人关了，整个问题都不存。
- `Idempotency-Key` 是 `qq-{群号}-{消息 ID}-thread` 或 `qq-{群号}-{消息 ID}-post`。
- 图片由论坛在发帖时转存。每轮最多攒 10 分钟，赶得上图片链接过期之前。

### 8.3 跟进多久

- 不按时间算，按群里后来又有多少条消息算：问题的最后一条相关消息之后，群里又过了 200 条消息，就不再跟进。到那时问题早就被刷上去了，很难再有人回答。
- 群很安静时，问题可以跟进很久。
- 不再跟进以后，引用了已收录消息的回复还是照收，用 `GET /bot/messages` 问论坛这条属于哪个帖子。
- 跟进中的问题只在内存里，插件重启就丢了；已经发出的帖子，靠引用还能接着收。

### 8.4 以后再说

- 同一个问题反复问，会有很多相似的帖子。先看历史记录里有多少，再决定要不要用 `GET /search/similar` 让大模型判断后并进旧帖子。
- 图片给大模型看：现在大模型只看到"[图片]"，只有截图没有文字的提问可能认不出来。
- 合并转发、文件和语音，按论坛的规则显示成"[聊天记录]"等，不展开。

### 8.5 用历史记录调效果

不做试运行，用维护者手里的历史群消息调。

- `tools/replay.py` 读入历史消息，按顺序跑一遍第 8.1–8.3 节，输出本来会发的帖子：标题、版块、标签、提问，以及收进去的回答。
- 跑的时候不连论坛。大模型用 OpenAI 兼容的接口，地址、密钥和模型从环境变量读。
- 同一份逻辑在 AstrBot 里调 `llm_provider`，在脚本里调这个接口。
- 用它定门槛、提示词和版块：先让模型给每个问题自由写一个类别，统计出来，再在论坛后台建版块和标签。

## 9. 通知

**开奖结果**（`lottery.drawn`）：发到 `lottery_groups`，空的发到主群：

```text
【抽奖开奖】鼠群周年抽奖
一等奖：机械键盘 @鼠鼠
二等奖：鼠群周边 @阿柒 @夜猫子 @Rex
共 25 人参与
https://bbs.mousebaoyan.cn/t/42
```

- 一条最多 @ 20 个人，再多的只写名字。
- 没人中的奖项写"无人中奖"。

**论坛的提醒**：论坛直接发邮件到 `QQ号@qq.com`，有提醒就立刻发，插件不参与。bot 不加好友，主动发临时会话又是典型的机器人特征，所以不用 bot 私聊。

## 10. 撤回

群友撤回自己的消息，而这条消息是论坛上某一层的来源时，以本人的身份删掉那一层：
- 撤回的人就是发送者，从 `group_recall` 里看；
- 是不是来源，用 `GET /bot/messages` 查；
- 是主楼就删整个帖子；帖子已经有人回复的，论坛不让删，就留着。

管理员撤回别人的消息，插件不跟着处理。

## 11. 事件流

只订阅 `member.activated` 和 `lottery.drawn`。

- 先用 `GET /bot/events/batch` 把游标之后的事件补完，再连 `GET /bot/events`（SSE，带 `Last-Event-ID`）收新的。
- 补发时看得到事件的时间。超过 12 小时的开奖不再发到群里，只往前推游标，免得插件停了一天，一开机就发一堆过时的结果。
- 每处理完一个事件，把游标存进 `state.json`。
- 游标过期（`410 cursor_expired`）时从 `latest_id` 重新开始，记一条警告。
- 第一次启动没有游标，从当前最新的事件开始。
- 断线后隔 1、2、5、10、30 秒重连，之后每 60 秒一次，每次都先补发。

## 12. 论坛要配合改的

- 提醒：
  - "QQ 提醒"换成"邮件"：有提醒就立刻发到 `QQ号@qq.com`。没登录过论坛的群友也发，他们在群里问的问题被收录后，有人在论坛上回答，就靠这封邮件知道。
  - 在论坛上回复一个帖子、没指定回复哪一层时，楼主也收到"回复我"。
  - 来自群聊的内容（带 `source`）不触发任何提醒。
  - 去掉 `notification.created` 事件和各事件里的 `qq_text`，插件不再用。
- 发信：SMTP 从个人 QQ 邮箱换成邮件推送服务，后台的 SMTP 设置不用改。
- 版块：初始版块都公开，包括闲聊；收录要用的版块等历史记录跑出来再定（第 8.5 节）。
- 总体设计：
  - §14 的 M9 改成现在的范围，并链接到这份文档。
  - §1、§8.6 去掉转存回执和 bot 私聊提醒。
  - §6.3 的推荐频率改成：全量读 NapCat 的缓存，每小时一次。
  - §8.10 去掉"插件提供命令"。
- 接口：
  - 去掉记回执用的 `PUT /bot/messages` 和 `kind: notice`；`GET /bot/messages` 留着，撤回和收录都要用。
  - `PATCH /me` 说明里的"插件的'不给访客看'命令"去掉。
- 页面：
  - 登录页改成"私聊机器人发送 登录"。
  - 后台创建 token 时，提示插件需要的几个范围。

## 13. 测试

- 单元测试（pytest）：
  - 用假的论坛（httpx 的 `MockTransport`）、假的 OneJev、假的大模型，以及假的 NapCat 和 AstrBot 事件。
  - 测：通知转增量，全量，登录的解析和错误回复，收录（分轮、规则、跟进的条数、引用直接收、发帖的请求头和幂等键、`proxy_disabled` 时跳过），撤回，事件流的补发和游标，开奖消息。
