## 1. 目标

AstrBot 插件，把鼠群的 QQ 群和鼠洞论坛连起来（论坛总体设计 §14 M9）。它只做这几件事：

- 登录入口：私聊 bot 登录论坛。
- 群成员同步到论坛。
- 自动收录：群里和保研、学业有关的正经提问和有信息量的讨论，连同群友的回复，一段讨论停下来就收，一般一小时内收进论坛，由大模型整理成论坛的帖子和回复，分好版块和标签；每天上午 9 点在群里发一条汇总，@ 发帖的人，附上帖子链接（第 8 节）。
- 开奖结果发到群里。
- 每周日晚上在群里发周榜图片，有人得到金徽章时在群里祝贺（第 9 节）。
- 群里问过的问题在论坛上有了新回答，在群里引用那条提问告诉楼主；有人进群时欢迎；群友发了帖子的链接，补一张写着标题和回复数的卡片（第 9 节）。

论坛的其他提醒由论坛自己发邮件到 `QQ号@qq.com`，不经过插件（第 9 节）。

不做：
- 群里的命令：转存、"不给访客看"、参与抽奖、搜索，都到论坛上操作。
- 主动私聊，自动通过好友申请。
- LLM 审核。
- 群公告、精华消息和群荣誉的同步。

## 2. 防风控

QQ 的风控会识别"像机器人"的账号，插件尽量让 bot 的操作和真人没有区别：

- 群消息和通知只被动接收。
- 读 NapCat 只读它的缓存，不让它为插件额外去 QQ 服务器拉数据。
- 不主动私聊别人，私聊只回复本人发来的消息（登录）。
- 回复（私聊登录、群里的"登录请私聊我"、链接卡片）前随机等 1–2 秒，不在收到消息的同一瞬间回。
- 主动发到群里的只有开奖结果、每天一条的收录汇总（第 8.8 节）、"猜你想问"的回复（第 8.11 节，每个群每 10 分钟最多 2 条）、每周一次的周榜、金徽章的祝贺、新回答提醒（9–23 点每半小时一轮，每个群每小时最多 3 条，每条前随机等 1–5 分钟）、入群欢迎（10 分钟内进群的合成一条，同一个群至少隔 2 小时）和链接卡片（同一个帖子在一个群里 30 分钟最多一次）（第 9 节）。
- 发出的消息尽量不带链接，必须带的只有登录链接、开奖结果、收录汇总、"猜你想问"、周榜、金徽章、新回答提醒和入群欢迎。链接卡片不带链接，原消息里已经有了。

插件让 NapCat 做的事只有这些：

| 操作 | 会不会请求 QQ 服务器 | 什么时候 |
| --- | --- | --- |
| `get_group_member_list`、`get_group_info`，都不带 `no_cache` | 不会，读 NapCat 的缓存 | 每小时；有人进群时 |
| `get_stranger_info` 查个性签名 | 会 | 有人第一次登录论坛时 |
| 私聊回复登录 | 会 | 本人私聊 bot 时 |
| 发开奖结果 | 会 | 开奖时 |
| 发收录汇总 | 会 | 每天上午 9 点，每个群最多一条 |
| 发"猜你想问" | 会 | 有提问能用论坛上的帖子回答时，每个群每 10 分钟最多 2 条 |
| `get_group_msg_history` 读群的聊天记录 | 一般不会，读 QQ 客户端本地的消息；客户端离线期间的，它登录后自己同步 | 插件启动时和每 10 分钟一轮，从每个群上一轮收到的最后一条读到现在，一页 100 条，翻页间隔 1 秒 |
| `get_qun_album_list` 找周榜的群相册 | 会 | 发周榜前，每个群一次 |
| `send_packet` 发 QQ 的建相册请求（AddAlbum） | 会 | 群里还没有"鼠洞周榜"相册时，只建一次 |
| `upload_image_to_qun_album` 传周榜图片 | 会 | 每周日 20 点，每个群一张；QQ 会在群里自动发一条相册动态 |
| 发周榜的文字版 | 会 | 传完图片，每个群一条 |
| 发金徽章的祝贺 | 会 | 有人得到金徽章时，只发到 TA 在的群 |
| 发新回答提醒 | 会 | 9–23 点每半小时一轮，每个群每小时最多 3 条，每条前随机等 1–5 分钟 |
| 发入群欢迎 | 会 | 有人进群后 10 分钟，这段时间进群的合成一条；离这个群上一次欢迎不到 2 小时的，等满 2 小时 |
| 发链接卡片 | 会 | 群友发了帖子的链接，同一个帖子在一个群里 30 分钟最多一次 |

- `get_group_member_list` 带 `no_cache: true` 时，NapCat 会在后台重新拉名单，却仍然先返回旧的缓存，所以插件从来不带。
- `get_group_member_info` 默认就强制刷新，还会多查一次这个人的资料，所以插件不用它。
- 自动收录平时只读收到的群消息；只有补漏掉的消息时读聊天记录（第 8.1 节），和人往上翻聊天记录一样。消息里的图片由论坛去 QQ 的图片域名下载（第 8.1 节），和群友在 QQ 里点开图片一样，不经过 NapCat。

开奖结果、收录汇总、"猜你想问"、周榜（建相册、传图片、文字版）、金徽章的祝贺、新回答提醒、入群欢迎和链接卡片排队发，间隔 3–6 秒随机。AstrBot 里有维护者其他插件共用的操作协调器（`platform_manager._qq_automation_guard_v1`）时改走它，和那些插件一起排队，共用账号的发送间隔和掉线后的冷却。

## 3. 运行环境

- AstrBot 4.26.2 以上、5.0 以下，Python 3.12 以上（这些版本的 AstrBot 本身就要求 3.12）。通过 aiocqhttp 反向 WebSocket 接 NapCat，接口按 NapCat 4.18 核对；只支持 aiocqhttp。
- 插件主动连接论坛（REST 和事件流），所在的机器能访问外网就行，论坛不反向连接插件。
- 自动收录还要：
  - 一个大模型（整理）和一个嵌入模型（embedding，查重，第 8.5 节），都走 OpenAI 兼容接口。大模型现在用 ECNU 的 `ecnu-plus`；嵌入模型用 bge-m3，跑在维护者家里的电脑上（比如用 Ollama），也可以用 ECNU 的 `ecnu-embedding-small`。
  - 插件直接调这两个接口，不经过 AstrBot 的模型配置：AstrBot 的 `llm_generate` 会丢掉每次请求自带的参数，传不了结构化输出和思考模式。回放用的也是同一份客户端和同一份配置（[回放实验](replay.md)第 3 节）。
- 依赖 httpx 和 numpy，AstrBot 已经自带；周榜要排版成图片，还要 Playwright，和维护者的[群聊摘要插件](https://github.com/JunieXD/astrbot_plugin_qq_group_digest)一样，第一次要在 AstrBot 用的 Python 环境里运行 `python -m playwright install chromium`。不发周榜的不用装浏览器。群里还没有周榜相册时要建一个，NapCat 没有建相册的动作，插件照群聊摘要插件的做法用 `send_packet` 发 QQ 自己的请求，要 NapCat 的 PacketBackend 能用。
- 论坛的 token：管理员在后台的 bot 页创建，bot 的 QQ 号填机器人自己的，范围选 `read`、`act`、`sync`、`auth`、`events`；自动收录要建标签，再加 `moderate`。建收录用的版块时临时加上 `admin`，建完去掉（第 8.9 节）。
- AstrBot 开了会话白名单的，要放行已同步的群，否则群消息和通知到不了插件。私聊不受白名单影响：白名单在所有插件之前检查，而且没法放行所有私聊，所以插件直接在 aiocqhttp 的客户端上订阅私聊消息（第 7 节）。
- 本机时间要准：论坛拒收比服务器时间晚 10 分钟以上的同步数据。

回放要调的数（一段的大小、跟进多久、相似的门槛）做成配置，调好后改默认值，不用改代码。其他频率和间隔写成常量，见下面各节。

## 5. 结构

```text
NapCat ⇄ AstrBot（aiocqhttp）
           └ 鼠洞插件
               ├ 群消息 → 自动收录（含撤回）
               ├ 私聊 → 登录
               ├ 群通知 → 成员增量
               ├ 每小时 → 成员全量、群资料
               ├ 群消息 → 链接卡片
               ├ 进群 → 入群欢迎
               ├ 每周日 → 周榜
               ├ 每半小时 → 新回答提醒
               └ 事件流 → 开奖结果、金徽章、个性签名
                     ⇅ REST、SSE（Bearer token，X-Act-As）
                  鼠洞论坛
自动收录另外调用大模型和嵌入模型（OpenAI 兼容接口）
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | AstrBot 入口：注册监听，启动、停止后台任务 |
| `mousehole/forum.py` | 论坛接口：请求头、gzip，错误转成 `ForumError(code, message)` |
| `mousehole/qq.py` | 调用 NapCat；回复前的延迟，主动发的消息排队；找、建群相册和传图片 |
| `mousehole/sync.py` | 成员同步 |
| `mousehole/login.py` | 私聊登录 |
| `mousehole/archive.py` | 自动收录：存消息、分批分段、跟进、发帖和更新、撤回、汇总 |
| `mousehole/judge.py` | 自动收录给大模型的提示词，和它输出的检查 |
| `mousehole/similar.py` | 查重：帖子的向量索引，找和新提问最像的帖子 |
| `mousehole/events.py` | 事件流，以及它触发的开奖结果、金徽章的祝贺、个性签名和向量索引的更新 |
| `mousehole/weekly.py` | 周榜：取论坛的统计和头像，排成 HTML，用 Chromium 截成图片，传进群相册，再发文字版；`mousehole/poster/` 是它用的字体（SIL OFL） |
| `mousehole/answers.py` | 新回答提醒：每轮取论坛上的新回答，隔开时间发到群里 |
| `mousehole/welcome.py` | 入群欢迎 |
| `mousehole/cards.py` | 链接卡片 |
| `tools/fake_forum.py` | 内存里的假论坛，单元测试和回放用 |
| `tools/boards.py` | 按 `data/boards.json` 在论坛上建版块和标签（第 8.9 节） |
| `tools/replay.py` | 用导出的历史群消息离线跑自动收录（[回放实验](replay.md)） |

论坛是唯一的数据源，插件几乎不存东西。数据目录（`data/plugin_data/astrbot_plugin_mousehole/`）里：
- `state.json`：事件流的游标；
- `pending/{群号}.jsonl`、`batch/{群号}-{时间}.jsonl`：等着收录的群消息，和正在收的这一轮里还没收的，收完就删（第 8.1 节）；
- `summary.json`：还没发的收录汇总（第 8.8 节）；
- `weekly.json`：这周的周榜发到了哪些群（第 9 节）；
- `answers.json`：新回答提醒查到了什么时候，一天内提醒过哪些帖子（第 9 节）；
- `threads.npz`：帖子的向量索引，丢了可以从论坛重建（第 8.5 节）。

谁在哪个群、跟进中的问题只放在内存里。

## 6. 成员同步

| 内容 | 做法 | 时机 |
| --- | --- | --- |
| 同步哪些群 | `GET /bot/groups`：后台关联且启用的群，主群在前 | 启动时、每小时 |
| 完整成员名单 | `get_group_member_list` 的结果原样转给 `PUT /bot/groups/{群号}/members`，带全部字段，gzip 压缩 | 启动后，之后每小时 |
| 群名、人数 | `get_group_info` → `PUT /bot/groups/{群号}/info` | 和全量一起 |
| 进群、退群、管理员、群名片、专属头衔 | QQ 通知转成增量，`PATCH /bot/groups/{群号}/members` | 收到通知时 |

NapCat 自己维护成员缓存，插件只读它（第 2 节）。不管有没有插件，NapCat 都会：
- 启动时拉一遍所有群的名单；
- 有人进群、退群、管理员变动时，先重新拉这个群的名单再发通知；
- 有人改了群名片，等他下次发言时更新。

所以缓存够新，全量每小时读一次就够了。

- 进群时，从缓存的名单里取出这个人的记录一起推，账号一建好就有名字。
- 缓存里的最后发言时间只在 NapCat 重新拉名单时更新。插件本来就在看群消息，全量时用看到的最近发言时间，替换缓存里更早的。
- `observed_at`：全量用读缓存的时间，增量用通知里的 `time`。
- 通知按论坛接口 §4.2 的表转换；专属头衔是 `notify` 通知，`sub_type` 为 `title`。
- bot 自己被踢（`kick_me`）或者群解散（`disband`）不推送，只记日志，由管理员在后台停用这个群。
- 全量被骤减保护拦下（`held`）时记一条警告。

头像不经过插件，论坛每天自己从 QQ 头像接口拉。个性签名由插件推：收到 `member.activated` 时，用 `get_stranger_info` 查 `long_nick`，推给 `PUT /bot/users/qq:{QQ号}/bio`。

## 7. 登录

私聊 bot，以"登录"开头的消息：

| 发送 | 做什么 |
| --- | --- |
| `登录`、`登录链接` | `POST /bot/auth/links`，回复一次性登录链接，10 分钟内有效，只能用一次 |
| `登录 482913`，或者只发 6 位口令 | `POST /bot/auth/code/confirm`，回复"已在 Chrome · macOS 登录鼠洞。不是你本人在登录的话，到鼠洞设置页的登录设备里让它下线。" |

- "登录"后面跟 6 位数字就是口令，其他都发链接。
- 私聊不走 AstrBot 的管线：插件在 aiocqhttp 的客户端上订阅 `message.private`，插件比平台先加载时（AstrBot 启动）在 `on_platform_loaded` 里订阅，停止时退订。管线里收到的登录私聊只 `stop_event`，免得 AstrBot 的大模型也回一句。
- 以发送者的身份调用（`X-Act-As` 和 `X-Operator` 都是发送者）。
- 群里 @bot 说"登录…"时，只回一句"登录请私聊我"。不 @ 的群消息不理会，群友聊天里说到"登录"很常见。
- 论坛返回的错误 `message` 本来就是给人看的，直接回复。几种常见的换成更具体的说法：

  | 错误码 | 回复 |
  | --- | --- |
  | `unknown_member` | 论坛还没同步到你，进群后稍等几分钟再试 |
  | `member_frozen` | 你已经不在鼠群里了 |
  | `login_code_invalid` | 口令不对或者过期了，刷新网页拿个新的 |

- 论坛连不上时回复"鼠洞暂时连不上，稍后再试"。
- 处理完停止事件传播，不让大模型再回。

## 8. 自动收录

群里正经的提问和讨论自动存成论坛的帖子，群友的回复存成回复：
- 只收和保研、升学、学业、科研、实习求职有关的，比如"大家怎么用 GPT 辅助科研"收，"GPT 的订阅怎么买"不收。群里常聊的 AI 工具、翻墙、数码、游戏这些话题，聊得再有信息量也不收：论坛的内容集中在保研上，大模型也不用在这些对话上花 token（第 8.2 节）。
- 提问：在请教这些方面的知识、经验、信息或建议，别人能回答、以后的人也可能会查的，都收。存成问答帖。
- 讨论：没有人专门提问，但几个人围绕这些方面的一个具体的情况或话题交换了有信息量的经验、观点或消息，以后的人也可能会查的，也收，存成讨论帖。发帖人是发起这个话题的人。只有情绪、玩笑、吐槽的不收。
- 没人回答的提问也收：论坛上的人看到了可以回答，补上 QQ 群容易把问题刷过去的短处。
- 一个问题、一个回答常常分好几条发。大模型把同一个人的几条整理成一层：提问的整理成主楼，写清问题和背景；回答的整理成一层回复。后来补充的，更新进原来那一层。
- 不边聊边收：群里安静下来、一段讨论停了再收，一般不到一小时（第 8.1 节）。一段讨论能整段交给大模型，零星几条也不单独调一次。
- 一个问题或话题只开一个帖子：讨论了很多段、隔一阵又有人问，都并进已有的帖子（第 8.5 节）。
- 版块和标签由大模型在收录时选好，版块默认都公开。
- 都记在本人名下，论坛上标"整理自群聊"。每天上午 9 点，bot 在群里发一条汇总，@ 前一天被收录的发帖人，附上帖子链接；提问并进了旧帖子的，告诉他论坛上已经有人问过（第 8.8 节）。
- 收录的内容不触发论坛的任何提醒，只有在论坛上发的回复才提醒（第 9 节）。

### 8.1 存消息、分批和分段

每个群的消息按到达顺序编号。规则先去掉这些，它们不存，也不给模型看：
- bot 自己发的；
- 命令：文字以 AstrBot 的唤醒前缀开头的；
- 只有表情的：QQ 表情（`face`）、商城表情（`mface`）、表情包（`image` 的 `sub_type` 为 1）。

短消息照收："不是""可以"这种两三个字的，常常就是回答；几条短消息合起来，才是一个完整的问题。

**存消息**：剩下的每条消息一到，就追加一行写进 `pending/{群号}.jsonl`：消息 ID、发送者、时间、OneBot 消息段，插件重启也不丢。
- 消息里的图片（不含表情包）当场用 `POST /uploads/fetch` 转存到论坛，论坛上的地址一起写进这一行：QQ 的图片链接几小时就过期，等到收录时已经取不到了。转存失败的记日志，这张图当作没有。
- 论坛会清理上传后 24 小时内没被引用的图片（论坛数据表文档）。消息最多等几个小时就收，图片早就用上了；没被收录的，正好由论坛删掉。
- 撤回的消息追加一行记下撤回，收录时去掉（第 8.7 节）。

**什么时候收**：每 10 分钟（`ROUND`，和猜你想问的同一个）看一遍各群等着的消息，一个群符合下面一条就收它一轮：
- 群里安静了 30 分钟（`QUIET`），并且攒了至少 20 条（`LEAST`），或者最早的一条已经等了 3 小时（`LONGEST`）。不够 20 条的接着等，合进下一轮：零星几条不单独调一次大模型，没人接话的提问最多等 3 小时。
- 一直没安静下来、攒到 150 条（`BACKLOG`）的：在最早的 75 条里找相邻两条隔得最久的地方切开（切口前至少 20 条），前面的收，后面的接着等，正在聊的不切断。

用 10 月 1–16 日的主群记录模拟：一天约 53 次调用（一天收两批时是 47 次），在讨论中间切开的次数差不多（44 次和 42 次，一段最多 50 条，本来就要切）；一半的消息 40 分钟内收进论坛，九成在 2 小时内。群里最忙的时候大模型生成得慢，会落后几个小时，安静下来再追上。

收一轮时，把这个群的 `pending/{群号}.jsonl` 改名成 `batch/{群号}-{时间}.jsonl`，只收前一部分的，后面的写回新的 `pending`；收录期间新来的消息也写进 `pending`，归下一轮。几个群都要收时一个收完再收下一个，同时只有一个大模型请求。
- 每收完一段，`batch` 里的文件改写成只剩还没收的消息，整轮收完删掉。插件在收录中途重启的，开机后接着收剩下的。
- 每一轮也顺便从论坛取一遍版块和标签（第 8.3 节）；取不到的，这一轮留到 10 分钟后。
- 插件没开着的时候（比如电脑关机）不收；开机后照常一轮一轮看，等太久或者积太多的马上就收。上午 9 点的汇总错过了，开机后马上发。
- **补漏**：插件、AstrBot 重启或者和 NapCat 断开的时候，群里的消息插件收不到。所以插件启动时和每一轮，都从每个群上一轮收到的最后一条消息起，用 `get_group_msg_history` 把聊天记录一页页往前读（第 2 节；往前翻页要带 `reverse_order`，不带的话 NapCat 从 `message_seq` 往新的读，拿回来的还是最新那一页），`pending` 里没有的消息照常存下、转存图片。读到的和收到的按消息 ID 去重。读聊天记录出错的（比如 NapCat 还没连上），这一轮照收已经有的消息，记日志。
- 每个群上一轮收到了哪个时刻的消息、上一次汇总什么时候发的、收过哪些群，记在 `archive.json`。

**分段**：一轮的消息先切成段，每段调用一次大模型。一段最多 `archive.segment_messages` 条（默认 50 条，太长了大模型会想到输出上限，第 8.2 节）：
1. 整轮超过上限时，从相邻两条消息隔得最久的地方切开；切出来的还超过上限的，照样再切，直到每段都不超过上限。一段讨论中间很少有长的空档，所以尽量整段留在一起。
2. 再把相邻的几段合起来，只要合起来不超过上限：夜里零星的几条消息不用各占一段，每段的系统提示词这些固定开销省下来。

一段一段按时间顺序收，一段的帖子都发完、记下了才收下一段（第 8.5 节）。

给模型看的消息每条一行：编号、作者代号、引用了哪条、文字。

```text
#1203 U4 ↩#1201 看学校，有些可能是不好撤回
```

- 作者写成 U1、U2……，每个群一套，插件运行期间不变。不给模型看 QQ 号和群名片。
- 编号也是插件运行期间每个群一套，从文件读回来时接着编。
- @ 某人写成 @U3；图片写成"[图片]"；文件、合并转发、卡片写成"[文件]""[聊天记录]""[卡片]"。
- 引用的消息不在这一轮、也不在内存里时写"↩更早的消息"。
- 已经收进论坛的消息后面标上它所在的那一层，比如"〔已收：Q2〕"；收成回应的标"〔已收：回应 A1〕"。

### 8.2 每段都交给大模型

不先用小模型筛一遍：试过用 OneJev 判断一段里有没有值得收的，回放里有内容的段和闲聊的分数混在一起，定不出既不漏、又能挡掉多数闲聊的门槛。没东西可收的段，大模型连思考只输出几百到一千多 token，花得不多。省钱靠三样：只收保研和学业相关的（第 8 节），不相干的对话大模型很快就判完；不够 20 条的等着合进下一轮；相邻的小段合起来（第 8.1 节）。

ECNU 的计价和限制（[配额限制](https://developer.ecnu.edu.cn/vitepress/llm/limit.html)）：
- `ecnu-plus` 每百万 token 输入 100 积分、输出（含思考）400；8–18 点翻倍。每个账号滚动 7 天 2 万积分。两个主群一天共约 3,000 条，一半在 8–18 点，收下来一天约 200 积分，7 天约占额度的 7%。
- 请求开头和前几分钟的请求相同的部分（比如系统提示词）命中缓存，只算五分之一。实测缓存只留 3–6 分钟；一轮里的段一个接一个调，系统提示词大多能命中；隔了几轮的不命中，只是一段多花一点。
- 同一个令牌、同一个模型最多 3 个请求同时在跑，和其他插件共用；超了直接返回 `429`，不扣积分。插件遇到 `429` 每 15 秒重试一次，最多 10 分钟，这一段排着等，不丢。
- 回答用流式（`stream`）传回来。ECNU 每秒只生成 20–30 个 token，一段想得多时要好几分钟；非流式的请求只能按总时长设超时，设短了会在生成到一半时断开，而断开后对方可能照样生成、照样扣积分。流式时超时只管多久没收到新内容（`llm.timeout_seconds`），生成多久都不打断。

- 思考会随一段的消息数变长：讨论密集时每条消息要想 250–300 个 token，50 条就有一万多，所以 `llm.max_tokens` 设到 32768（ecnu-plus 最多 128K），一段也不超过 50 条。想到上限的回答没有完整的 JSON，照样扣积分，只能切成两半重收（见下面的表）。同一段消息每次想的长短也差得多，回放里有一段 43 条的，两次想了 8–11k，一次超过了 32k。

#### 出错时

夜里收录没人看着，所以分两类处理：服务暂时不可用的，等一会儿再收，这一段不丢；这一段本身的问题，丢掉这一段，接着收下一段。

| 情况 | 做法 |
| --- | --- |
| 大模型的连接断了、回答没传完就停了（流里没有 `finish_reason`）、多久没收到新内容、`5xx` | 隔 30 秒、2 分钟、5 分钟各再问一次。断开的调用几乎不扣积分 |
| 再问还不行，`429` 排了 10 分钟（ECNU 的积分用完也是 `429`），`401`、`403`（令牌失效、IP 不在白名单）、`402`（Step Plan 的额度用完了），或者当天的 token 用完了 | 这一轮停下，这一段留在 `batch` 的文件里，10 分钟后（`PAUSE`）接着收 |
| 论坛连不上、返回 `5xx` 或 `401`（bot token 失效），嵌入模型连不上 | 同上，这一轮停下，10 分钟后接着收 |
| 想到了 `max_tokens`（`finish_reason` 为 `length`） | 从这一段中间最长的空档切成两半，各收一次：同样的一段再问多半还是想那么久，消息少了想得就短。讨论密集的段最有内容，不能丢 |
| `4xx`、输出不是 JSON | 这一段作废，记日志，接着收下一段：再问一次多半一样，白花积分 |

- 每次接着收之前，先取一遍论坛的版块和标签、调一次嵌入模型，都通了才调大模型：大模型的积分花了、发帖时才发现论坛或嵌入模型不通，这一段就得重收，再花一遍。嵌入模型在维护者家里的电脑上，夜里关机很常见。
- 停下的那一段重收时，已经发出去的帖子和回复靠幂等键和 `source_exists` 认出来，不会重发（第 8.4 节），汇总里也不重复写。
- 向量索引（第 8.5 节）也在这一步建，建不成就和上面一样等着，插件启动时嵌入模型不通也不影响别的功能。
- 论坛的请求也会自己重试：连接被拒、网关返回 `502` 或 `503`（论坛在重启），隔 1、3、10 秒再发。只发一次就有效果的请求（发帖、建标签、登录），只在请求没发出去、或者带了幂等键时重发，免得做两遍。插件启动时论坛连不上的，每分钟再试，连上了才开始成员同步和事件流。
- 等到点用墙上的时钟，每分钟看一次，电脑睡眠醒来后照样按时收。
- `pending` 的文件是一行一行追加的，断电时最后一行可能没写完，读的时候跳过这一行。
- 汇总发不出去（比如 NapCat 掉线）的，10 分钟后再发，发出去为止。

### 8.3 大模型整理

每一段调用一次大模型（`llm`）。这一次做完所有事：
- 认出新的提问和讨论，起标题，选版块和标签；
- 把同一个人的几条整理成一层；
- 判断回答的是哪个问题；
- 把后来补充的内容更新进已有的那一层。

输入：
- 跟进中的问题（第 8.6 节）：编号 Q1、Q2……，标题，主楼的正文，已有的回答（编号 A1、A2……，作者代号，正文）。每一层都带上它收进的原消息，更新时从原消息重新整理。
- 上下文：这一段前面的 20 条。没收过的可以和这一段的消息合成一层，比如提问的前半句在上一段。
- 这一段的消息。
- 论坛上成员能发帖的版块（`GET /boards` 的 slug、名字、说明）和已有的标签（`GET /tags`），每一轮开始时取。

输出 JSON：

```json
{
  "new": [
    {
      "ref": "N1",
      "type": "question",
      "messages": [1201, 1204],
      "title": "预推免的第一批和第二批能都报吗",
      "body": "常说的预推免第一批、第二批，是一个人只能报其中一批吗？",
      "board": "qa",
      "tags": ["预推免"],
      "same_as": null
    },
    {
      "ref": "N2",
      "type": "reply",
      "question": "N1",
      "messages": [1203, 1207],
      "body": "看学校，有些学校报了以后不好撤回。",
      "reply_to": null
    }
  ],
  "edit": [
    { "post": "Q1", "messages": [1210], "title": null, "body": "……整理后的完整正文" }
  ],
  "react": [
    { "message": 1206, "post": "N2", "emoji": "+1", "boost": "确实" }
  ]
}
```

- `new` 是新的一层：`type` 为 `question`（提问）开问答帖，为 `discussion`（讨论）开讨论帖，为 `reply` 是回复，发在它所在的帖子里。`question` 填跟进中的问题（Q1）或这一段新的提问（N1）。`reply_to` 填它回复的那一层，回复的是问题本身时为空。
- 提问和讨论的 `new_tags` 是要新建的标签，`[{"name": "……", "kind": "school"}]`，没有就是空的；同一项的 `tags` 里可以用它们（第 8.9 节）。
- `edit` 是更新已有的一层：`messages` 是新补充的消息，`body` 是用这一层原来的消息加上新补充的重新整理出的完整正文，`title` 只在主楼、需要改时填。每次都从原消息整理，不在上一版正文上改，大模型写偏了的地方不会一版版累积下去。
- `new` 的每一项都带 `author`，这一层是谁说的（作者代号），`messages` 只能是这个人的消息，对不上的这一项丢掉。先写出作者，模型就不容易把几个人的话并成一层。
- `react` 是群里对某一层（主楼或回复）的接话，还原成论坛上的表情回应和短评：表达了赞同、喜欢、感谢、好笑、惊讶、佩服、恭喜、安慰、疑惑、难过的，给那一层加上这个人的表情（`emoji`，论坛的 10 个之一，没有这些情绪的为空）；算不上正经回复的接话，附和、表态、玩笑、调侃、感叹都算，留成短评（`boost`，不超过论坛的上限 16 个字），让帖子像真人在聊。带出了自己信息的收成回复；追问也是回复，有人回答了的，回答也收成回复。一条消息收进了回复的，还可以另外给它回应的那一层点表情，但不再留短评。不能回应自己的那一层。
- 一层只收一个人的消息，每条消息只收进一层。一个人连着说的同一段话是一层；他回应另一层的话（引用或 @ 那一层的作者）是新的一层，`reply_to` 填那一层，不并进他自己更早的那一层；连着回应同一层的几句话还是一层。帖子里谁在回谁和群里的对话一样：楼主交代自己情况的话写进主楼，他听了回答以后的回应、担心和新问题是他的回复。

开了结构化输出（`llm.structured_output` 为 `json_schema`）时，请求带上输出格式的 JSON Schema（`judge.py` 的 `ORGANIZE_SCHEMA`），ECNU 用受约束的解码保证输出一定是这个形状。每一项的字段都是必填的，用不上的填 null 或空列表：提问、讨论和回复共用一种对象，字段可以不写的话，回复会漏掉它挂在哪个帖子。内容对不对仍由下面的检查管。

规矩写在系统提示词里：
- 只收和保研、升学、学业、科研、实习求职有关的，别的话题不收（第 8 节）。
- 提问要自己能看懂、别人能回答。只有接着前文才看得懂的追问，算对应问题的回复，类型是 `reply`。附和、道谢、闲聊、玩笑、反问都不收。
- 讨论：没有人专门提问，但几个人围绕一个具体的情况或话题交换了有信息量的经验、观点或消息，类型是 `discussion`。发帖人是发起这个话题的人：主楼整理他抛出话题时说的情况，标题概括讨论的是什么；其他人的发言是回复。只有情绪、玩笑、吐槽、八卦的不收。
- 整理正文：写成本人在论坛上发帖、回帖的样子，读着顺，而不是把聊天记录拼起来：
  - 碎句改成通顺的话，可以调整语序、合并重复的意思，去掉表情、语气词、口头禅和跟问题无关的话；主楼先交代情况、再说想问什么，内容多的分段；
  - 保持原意：只用本人说过的内容（主楼还可以写上他接着的话题），不加原文没有的信息，不替他下结论，不把别人回复里的说法写进他这一层；"也""都""不""只""可能"这类词的意思不丢，拿不准的照原话写，看不懂的网络用语和黑话原样保留；人称和口气是本人的；
  - 主楼要让没看过群聊的人看得懂：楼主在前文和这一段里说过的自己的情况（学校、rank、方向、进度、打算），包括回答别人追问时交代的，比如"rank 前 10%"，都写进主楼；问题是顺着群里正在聊的事问的，把这件事写进来，指代换成说的是什么。背景用楼主自己的口吻写，不写"群里聊到""看到群友说"；只补群里说过的，不替他加顾虑和理由，不用别人回答里的信息，缩写和黑话照抄；问题本身清楚、又找不到背景的，照他问的写，不加开场白。只问楼主情况的追问和问错字的追问，连同回答都不收；
  - 消息里的"[图片]"留在正文里图片该在的地方；
  - 学校、专业、数字、链接、缩写照抄；
  - 每一层最后不加句号，像论坛上真人回帖（大模型不总照做，插件发之前再去掉正文和短评结尾的"。"）；不写作者代号和 @；需要时用 Markdown 排列表、加粗、提示块等。
- 标题不超过 30 个字，像论坛的帖子标题，说清楚问的是什么。
- 版块只从给的里选。标签最多 5 个，先从已有的里选；没有合适的、又是以后会反复用到的院校、方向或话题，可以起新标签（`new_tags`，名字和类别，第 8.9 节）。
- 跟进中的问题：接着讨论、追问、补充它的，是回答或更新，不是新的提问；提问的人把没人回的问题再问一遍，比如"有人知道吗"或者换个说法，是更新原来的主楼。
- `same_as`：别人问了和跟进中的问题、或者这一段另一个新提问同样的问题时，填它的编号（Q1 或 N1，第 8.5 节）。

用户提示词里不常变的放在前面：版块、标签，再是跟进中的问题，最后是前文和这一段的消息。大模型服务按前缀缓存，前缀不变的部分按缓存价计费。

插件检查输出：编号和消息都要存在，已经收过的消息去掉（第 8.5 节），`edit` 至少要有一条新消息，同一层的消息要是同一个人的，版块要在列表里，标签只留已有的，标题截到 30 个字。不合格的那一项丢掉、记日志；整个不是 JSON 的，这一段作废，记一条警告。

回放实测（夜间价）：每段输入 1.5–6k token，其中系统提示词约 1.3k。不相干的闲聊，一段输出连思考几百到一千多 token，不到 1 积分；讨论密集的，每条消息约 0.07 积分。一个群一天约 1700 条有效消息，估计一天 100 积分左右，约占每周额度的 3.5%。一段多大由回放定（[回放实验](replay.md)第 5.1 节）。

### 8.4 发帖和更新

| 输出 | 调用 | `X-Act-As` |
| --- | --- | --- |
| 新的提问或讨论 | `POST /threads`：类型是问答（`question`）或讨论（`discussion`），标题、版块、标签用大模型给的 | 提问或发起讨论的人 |
| 新的回复 | `POST /threads/{帖子 ID}/posts`，`reply_to_id` 是它回复的那一层 | 回复的人 |
| 更新 | `PATCH /posts/{楼层 ID}`；改标题时再 `PATCH /threads/{帖子 ID}` | 那一层的作者 |
| 回应和短评 | `PUT /posts/{楼层 ID}/reaction`，有短评时再 `PUT /posts/{楼层 ID}/boost`，都带 `source`（那条消息）和 `created_at`，论坛不提醒楼层作者 | 表态的人 |

- 内容用 `content.markdown`：整理好的正文，里面留下的"[图片]"按原来的顺序换成这些消息里的图片（不含表情包），没换到的接在正文后面。只发了图片的消息，大模型没收进哪一层的，插件并进同一个人紧挨着说的话所在的那一层（先找后面的，再找前面的），图片不会丢。图片在消息到的时候就转存到论坛了（第 8.1 节，存在论坛服务器的数据卷里，和网页上传的图片一样），发帖和更新都给论坛上的地址。
- 发帖、回复、回应和短评都带 `created_at`，是这一层第一条消息在群里发出的时间，论坛上显示的就是群里说这句话的时间，不是收录的时间（论坛接口 §2.5）。
- `source` 是这一层收进的全部消息，按在群里发出的先后排：`{ chat_type: "group", chat_id: 群号, message_ids: [...] }`，论坛用它查某条消息属于哪一层（`GET /bot/messages`）。更新时带上完整的新列表。
- 本人在论坛上改过这一层，就不再更新它：插件记下自己最后一次写入后的 `edited_at`，更新前对一下，不一样就跳过，记日志。
- 都不带 `X-Operator`，因为自动收录没有操作人。论坛拒绝以这个人的身份发（比如他关了"允许代发"，`403 proxy_disabled`）时，插件跳过这一层；提问的人被拒绝时，整个问题连同回答都不收。
- `Idempotency-Key` 是 `qq-{群号}-{第一条消息 ID}-thread` 或 `qq-{群号}-{第一条消息 ID}-post`。返回 `409 source_exists`，说明已经收过（比如插件中途重启），用返回的 `thread_id` 和 `post_id` 接着跟进。

### 8.5 不重复发帖

一个问题常常讨论很多段，每段都调一次大模型；同一个问题也常有人隔一阵再问。大模型每次写出的文字都不一样，所以判断收没收过、发没发过，只看消息编号和帖子编号，从不比较它写的文字。下面四层保证一个问题只开一个帖子、一条消息只收一次。

1. **一条消息只收一次**：大模型的输出里，每一层写的是它收进的消息编号（`messages`），不是原文。插件记着每个编号收进了哪一层，输出里已经收过的编号直接去掉，去掉后一层里没有消息了，这一项就丢掉，都记日志。论坛那边一条消息也只能属于一层，重复收会返回 `409 source_exists`。所以同一条消息不管大模型这次怎么写，都不会再发一遍。
2. **没有新消息就不改**：`edit` 至少要带一条新消息，否则丢掉，已经发出去的正文不会因为大模型换了个写法来回改。
3. **跟进中的问题每段都给大模型**，并且一段的帖子和回复都发完、记下，才收下一段（回复按在群里说的先后发；比帖子里已有楼层说得还早的，比如在提问之前就说了的，时间记成和那层一样，楼层的时间不倒着走），所以下一段一定能看到上一段开的帖子。接着讨论的写成回答或更新，同一个人再问一遍的更新原来的主楼，别人问了同样的问题填 `same_as`（第 8.3 节的规矩）。请求超时重试时带同一个幂等键，论坛只建一次。
4. **开新帖前查重**：大模型给出新的提问时，先找最像的帖子当候选，再调用一次大模型判断。它兜住第 3 层漏掉的，也管跟进不到的：问题过了 200 条又被问起，插件重启后跟进的问题丢了，隔几天又有人问。

前两层由代码保证，后两层要判断意思，靠大模型；第 4 层的候选找不找得全，决定了它能兜住多少。

#### 找候选

同一个问题换个说法很常见（"拿了优营不去会怎样"和"夏令营 offer 能鸽吗"），只按字面找会漏，所以两种一起用：
- **语义**：插件用嵌入模型（`embedding`）给论坛上每个帖子的标题和主楼开头算向量，存在 `threads.npz`，跟着事件流更新（新帖、主楼改了、帖子删了）。启动时没有索引或者换了模型，就从论坛分页取回全部帖子重建。新提问的标题加正文也算一个向量，取余弦相似度最高的 5 个。帖子上万个也只是几十 MB，直接用 numpy 逐个算，不用向量数据库。
- **字面**：论坛的 `GET /search/similar`，取最像的 5 个。它把中文切成相邻两个字，任何一个对上就算，按对上的密度排序，能补上学校名、缩写这类向量不一定分得清的。

两边合起来去掉重复，最多 10 个；语义相似度低于门槛（先定 0.5，用回放调）、字面也没对上的不算。最后一层回复（`last_post_at`）晚于这次提问的帖子也不算：并进去的一层会排在比它晚说的楼层后面，时间倒着走。历史收录晚于插件开收、几批同时收时都会碰到，这样的提问宁可另开新帖。没有候选就直接发帖。

#### 判断

有候选时调用一次大模型：新问题，和每个候选的标题、版块、日期、回复数、主楼开头 100 个字，问哪个和它是同一件事、旧帖子的回答能不能直接回答它。
- 问的是自己的情况（"我这个条件能去哪"），不算和别人重复；问的是不同年份的事，比如今年和去年的夏令营，也不算。
- 每次一两千 token，一天几十次。

判为重复的不开新帖：这个提问作为一层回复发在已有的帖子里（`X-Act-As` 是提问的人）。旧帖子不管多久以前的，并进去以后都和新开的帖子一样跟进（第 8.6 节）：群里接着的回答、追问和讨论，都收进这个旧帖子，回答默认回复提问的这一层。讨论同样查重：之前讨论过同一件事的，新的发言并进旧帖子。旧帖子锁定了或者删了（`thread_locked`、`not_found`），就照常开新帖。

并进旧帖子时，汇总会把提问的人引到旧帖子（第 8.8 节）。判错了，他会被引到一个不相干的帖子，比不提醒更糟，所以拿不准时当作不是；回放里单独评查重找得准不准（[回放实验](replay.md)第 5.3 节）。

### 8.6 跟进多久

- 不按时间算，按群里后来又有多少条消息算：问题的最后一条相关消息之后，群里又过了 200 条消息，就不再跟进。到那时问题早就被刷上去了，很难再有人回答。
- 群很安静时，问题可以跟进很久。
- 不再跟进以后，有人引用了已收录的消息，插件用 `GET /bot/messages` 查到这条消息在哪个帖子，从论坛取回帖子的主楼和最近的回答，重新跟进这个问题。取回的楼层只给模型作参考，不再更新。
- 跟进中的问题只在内存里，插件重启就丢了；已经发出的帖子，靠引用还能接上。

### 8.7 撤回

群友撤回自己的消息（`group_recall` 里撤回的人就是发送者）时，在 `pending` 里记一行；收录时这条消息不给大模型看，也不收。正在收的这一轮里还没收到的，同样去掉。

已经收进论坛的不跟着处理：群里普通成员只能撤回自己 2 分钟内的消息，而消息要等群里安静 30 分钟才收，所以撤回的几乎都还没收；管理员撤回自己很早的消息才会遇到，本人可以在论坛上删。管理员撤回别人的消息，插件也不跟着处理。

### 8.8 收录汇总

每天上午 9 点（`SUMMARY_HOUR`），每个群发一条汇总：从上一条汇总之后收录开的新帖子，@ 提问或发起讨论的人：

```text
鼠洞收录了群里的 2 个帖子：
1. @鼠鼠
预推免的第一批和第二批能都报吗
https://bbs.mousebaoyan.cn/t/42
2. @夜猫子
（讨论）夏令营机试的题型
https://bbs.mousebaoyan.cn/t/43
```

- 只写开帖的：提问、发起讨论的人。回复和更新不写。提问并进了旧帖子的也不写，问的时候"猜你想问"已经告诉过他（第 8.11 节）；并进旧帖子以后，群里接着的讨论照常收进旧帖子。
- 最多列 10 个（`SUMMARY_ITEMS`），多的写"还有 N 个，到鼠洞上看"和论坛的地址。一条汇总里 @ 的人不会太多，也不会长到刷屏。
- 没有收录新帖子的群不发。
- 收录时把要写进汇总的记进 `summary.json`，发完清掉，插件重启也不丢。9 点时还没收完的，收完的部分先发，剩下的进第二天的汇总；9 点插件没开着的，等第二天 9 点一起发。
- 和开奖结果一起排队发（第 2 节）。`archive.notify` 关掉就不发。
- 回放里记下本来会发的汇总：`summary.md` 里有发了几条，`threads.md` 里每个帖子标出写给谁。

### 8.9 版块和标签

- 版块：用回放跑出的类别定下（[回放实验](replay.md)第 6 节），维护者确认后建好版块和初始标签：用 `tools/boards.py` 按 `data/boards.json` 建，要 token 临时加上 `admin`；或者用站长账号在后台建。收录时大模型只从成员能发帖的版块里选。现在有保研问答、经验分享、通知、院校交流、科研与读研、实习就业、闲聊、反馈建议。
- 标签：大模型没有合适的已有标签时，可以给出新标签（名字不超过 20 个字，院校用全称，类别是 `topic`、`school` 或 `major`）。插件先用 `POST /tags` 建好再用，返回 `409 tag_exists` 就用已有的那个。每天最多新建 10 个，超了的这一项不带新标签，记日志。token 没有 `moderate`（`403 scope_missing`）时也一样，帖子照发，只是不带这个新标签。

### 8.10 历史收录

插件上线前的群消息，用 QQChatExporter 导出后由 `tools/history.py` 收录到论坛，和插件当时就在时收的一样：
- 按消息的时间分成 4 点、18 点的批次（`BATCH_HOURS`），一批一批收，规则、提示词和检查都用插件的同一份代码。不像插件那样讨论停下来就收：历史收录不用赶时间，一批里的讨论更完整，调用也少些。帖子、回复、回应都用群里发出的时间（第 8.4 节）。
- 消息 ID 用 2^40 加上消息在群里的序号：NapCat 给插件的消息 ID 都小于 2^31，两边分得开，论坛按它们去重；QQ 自己的消息 ID 有 19 位，超出了论坛的 JSON 能准确表示的整数（2^53）。图片从导出时下载的文件上传（`POST /uploads`），没下载的就没有。
- 退群的人：论坛还没见过的（论坛上线前就退群了），开收前用增量同步推一条 `in_group: false` 的记录，按导出里的昵称和群名片建账号，和后来退群的人一样是冻结的。论坛放行 bot 代表冻结的人发带来源的收录内容（论坛的接口文档 §2.3），所以他们的提问和回答照样收在自己名下；他们的图片用 bot 的账号上传，标题不改（改标题不带来源）。
- 不在群里发汇总。
- `--until` 之后的消息不收：插件开启自动收录以后的消息由插件来收，两边的消息 ID 不同，论坛去不了重，导出的范围要是和插件收的重叠，就要用它截开。几份导出重叠的部分按消息 ID 只收一次。
- 几批同时收（默认 5 个），每个各收一段连续的时间，共用一个向量索引，互相查得到对方刚发的帖子。查重只并进最后一层回复早于提问的帖子（第 8.5 节），插件已经收的和后面几段先发的帖子都并不进去，同一个问题可能有两个帖子。
- 每段收完帖子就已经发出去了；收到哪批记在 `done.txt`，每段的结果追加进 `segments.jsonl`。中途停了用同样的参数再跑，从断点接着收。
- 论坛限流（`429`）就按 `Retry-After` 等着再发；论坛、大模型、嵌入模型不可用就等 10 分钟再试。`--off-peak` 避开 Step Plan 的高峰时段（工作日 9–12、14–18 点 Step 5 Preview 按 2 倍扣）。
- 用法：`uv run python -m tools.history 导出.json… --config 配置 --data 目录`，配置和插件的一样，大模型可以换；先用 `--batches 1` 试一批。

### 8.11 猜你想问

群里有人提问，论坛上已经有帖子回答过的，bot 很快引用他那条消息回复，把帖子推给他。收录要等讨论停下来，这个每 10 分钟一轮（`ROUND`），问的人多半还在。

- **挑提问**：一轮看这 10 分钟里收录的群的新消息，在本地挑出像提问的：至少 6 个字，带问号或者"吗""怎么""哪""多少""有没有"这类词；冲着某个人问的（有"你"、不是"你们"）、bot 自己的和命令不算。不调大模型。用 10 月的群消息试，一天能挑出两百来条，大多还是闲聊，靠下一步筛掉。
- **找候选**：每个提问只用向量找（第 8.5 节"找候选"），相似度至少 0.65，最多 3 个；字面搜索会把闲聊也匹配上，这里不用。只留有回复的帖子，去掉提问人自己的帖子，以及 6 小时内已经在这个群推过的。用 10 月的消息对 144 个帖子试，门槛 0.6 时一天有 30 个提问有候选，大多是闲聊；0.65 时剩 7 个，一天调大模型 6 次左右。都没有候选就到此为止，多数时候一个 token 也不花。
- **确认**：有候选时，这一轮所有的提问连同各自的候选一次交给大模型，问哪些帖子能直接回答它（`judge.py` 的 `SUGGEST`，规矩同第 8.5 节的"判断"，拿不准时当作不能）。一轮一次调用。
- **回复**：引用那条消息，最多 3 个帖子，能回答得最好的在前：

  ```text
  猜你想问：
  1. 拿了优营不去会怎样
  https://bbs.mousebaoyan.cn/t/17
  ```

**新回答提醒**：群里问过、收录成问答帖的问题，后来有人在论坛上回答了，在群里引用那条提问告诉楼主。"猜你想问"是把论坛上的旧帖子推给群里的新提问，这个反过来，把论坛上的新回答带回群里。
- 9 点到 23 点每半小时一轮（`FIRST`、`LAST`），夜里不查，夜里的回答留到 9 点那轮。每轮取 `GET /bot/answers?since={上次查到}&until={现在减半小时}`，哪些算新回答由论坛定（论坛接口 §3.10）：在论坛上写的、不是楼主写的公开回答，楼主已经读过的不算。只查半小时（`SETTLE`）以前的回答：楼主这半小时里在论坛上看到了，就不打扰他；接连来的几条回答也合成一条提醒。第一次运行只记下时间，不发。
- 提问超过 48 小时（`FRESH`，按帖子的 `created_at`，也就是在群里提问的时间）的不提醒，楼主多半已经不关心了；历史收录的帖子因此都不提醒。
- 只发到提问所在的群（`source.chat_id`），这个群要还关联着、楼主还在群里，否则跳过；楼主退了这个群、还在别的关联群的，也不提醒。谁在哪个群靠成员同步时读到的名单，关掉成员同步就不提醒。
- 同一个帖子 24 小时内（`AGAIN`）只提醒一次，这期间再来的回答不另外提醒，楼主点进帖子自然能看到。
- 每个群每小时最多 3 条（`PER_HOUR`），超出的留到下一轮，这一轮查到的时间不往前推，下一轮从同一个 `since` 再查，已经提醒过的跳过。
- 每条提醒前随机等 1–5 分钟（`GAP`）再放进发送队列，一条一条地发。每发一条就把帖子和时间记进 `answers.json`；一轮没发完插件就重启的，下一轮接着发剩下的，不重复。
- 引用楼主提问的第一条消息（`source.message_id`），@ 楼主，链接到第一条新回答：

  ```text
  [引用：预推免第一批和第二批能都报吗]
  @鼠鼠 你问的「预推免第一批和第二批能都报吗」在鼠洞上有 2 条新回答：
  https://bbs.mousebaoyan.cn/t/42?floor=5
  ```

- 消息里写了标题，不靠引用也看得懂：NapCat 找不到原消息时（历史收录的消息，第 8.10 节；太早的消息）会去掉引用照发，插件不用分开处理。
- `answers.enabled` 关掉就不查也不发。

**入群欢迎**：有人进 `welcome.groups` 里的群（`group_increase`）时，在群里欢迎。
- 从第一个人进群起等 10 分钟（`welcome.py` 的 `WAIT`），这段时间进这个群的人合成一条；离这个群上一次欢迎不到 2 小时（`GAP`）的，等满 2 小时，这期间进群的也合进来。最多 @ 20 个，再多的不欢迎。等的时候插件重启了就不发。
- 不欢迎 bot 自己，也不欢迎已经在另一个关联群里的人（比如一群的人又进了二群），谁在哪个群看成员同步时读到的名单。
- 内容是 `welcome.template`，默认：

  ```text
  欢迎 {at}～群里的问答和经验都整理在鼠洞：{forum}
  私聊我发「登录」就能登录，记得按群公告改群名片
  ```

  新人必读之类的帖子，把链接直接写进模板。

**链接卡片**：群友的消息里有论坛帖子的链接（`{forum_url}/t/{帖子 ID}`，带 `?floor=` 的也算这个帖子）时，引用这条消息，补一张写着标题和回复数的卡片，让人知道值不值得点开。QQ 不给这类链接显示预览。
- 只看文字消息段；bot 自己发的不算。一条消息最多两个帖子，合成一条卡片。
- 以发链接的人的身份读帖子：`GET /threads/{帖子 ID}`，`X-Act-As` 是发链接的人。他看不到的（等级门槛、待审核、已删除，论坛返回错误）和不是公开状态的，不发卡片，不会把他看不到的标题发到群里。
- 同一个帖子在同一个群里 30 分钟（`CARD_COOLDOWN`）内只发一次，记在内存里。
- 不带链接，原消息里已经有了。问答帖写"✅ 已解决"或"待解答"，其他类型不写；还没有回复的写"还没有回复"，楼主匿名的写匿名的名字：

  ```text
  [引用：带链接的那条消息]
  「保研问答」预推免第一批和第二批能都报吗
  鼠鼠 · 5 条回复 · ✅ 已解决 · 120 次浏览
  ```

- `cards.enabled` 关掉就不发。

**话术模板**：bot 发的话，除了周榜的文字版，都能在配置里改，默认值就是上面各节的例子。
- 模板里的 `{名字}` 换成对应的内容，`{forum}` 在哪个模板里都是论坛地址；不认识的 `{名字}` 原样留着，写错了一眼就看得出来。多行文本，换行照写。
- 引用原消息（链接卡片、新回答提醒、猜你想问）不在模板里，照旧加上。
- `{at}` 换成 @ 那个人；一条消息最多 @ 20 个人的规矩照旧，超出的写名字。
- 带列表的消息分整条和每一项两个模板，`{items}` 换成一项一行。
- 改模板时照第 2 节：不要给不该带链接的消息加上链接。

## 10. 事件流

订阅这几种：
- `member.activated`、`lottery.drawn`、`badge.granted`：个性签名、开奖结果和金徽章；
- `thread.created`、`post.updated`、`post.deleted`：更新查重用的向量索引（第 8.5 节）。新帖取回主楼开头算向量；主楼改了（`floor` 为 1）用事件里的标题和正文重算；主楼删了就从索引里去掉。改标题没有事件，插件自己改的标题当场重算，别人改的等主楼再改时才跟上。

- 先用 `GET /bot/events/batch` 把游标之后的事件补完，再连 `GET /bot/events`（SSE，带 `Last-Event-ID`）收新的。
- 补发时看得到事件的时间。超过 12 小时的开奖和金徽章不再发到群里，只往前推游标，免得插件停了一天，一开机就发一堆过时的结果。
- 每处理完一个事件，把游标存进 `state.json`。
- 游标过期（`410 cursor_expired`）时从 `latest_id` 重新开始，记一条警告。
- 第一次启动没有游标，从当前最新的事件开始。
- 断线后隔 1、2、5、10、30 秒重连，之后每 60 秒一次，每次都先补发。

提醒改发邮件、多个发信邮箱、版块默认公开，新回答提醒的 `GET /bot/answers`（第 9 节），以及收录要用的接口（一层整理自几条消息、`PATCH /posts` 收消息段和完整的来源、"整理自群聊"的标注、去掉转存回执），论坛都已经改好（论坛总体设计 §6.3、§8.1、§8.6，接口 §2.5、§6.4）。还剩：
