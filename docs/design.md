# 鼠洞插件 · 设计

> 状态：草案，待评审。论坛一侧见鼠洞仓库的[总体设计](https://github.com/mousebaoyan/mousehole/blob/main/docs/design.md)和[接口](https://github.com/mousebaoyan/mousehole/blob/main/docs/api.md)；本文只写插件自己的部分，接口细节以论坛的文档为准。

## 1. 目标

AstrBot 插件，把鼠群的 QQ 群和鼠洞论坛连起来（论坛总体设计 §14 M9）：

- 群成员同步到论坛：全量、增量和群资料。
- 经 bot 登录：口令登录、一次性链接登录；成员第一次登录时推送 QQ 个性签名。
- 群消息转存成帖子并发回执，引用回执的回复同步进帖子。
- 论坛的 QQ 提醒私聊发给本人；抽奖开奖后把结果发到群里，@ 中奖的人。
- 群友在 QQ 里设置"我的内容不给访客看"、参与抽奖、搜索论坛。

不做：LLM 审核（以后接）；二期的播报、群公告和精华同步、聊天记录帖。论坛的内容不发回群里，发到 QQ 的只有论坛总体设计 §8.6 列的几种。

## 2. 运行环境

- AstrBot 4.26.2 以上、5.0 以下，Python 3.12 以上（这些版本的 AstrBot 本身就要求 3.12）。通过 aiocqhttp 反向 WebSocket 接 NapCat，接口按 NapCat 4.18 核对；只支持 aiocqhttp。
- 插件主动连接论坛（REST 和事件流），所在的机器能访问外网就行，论坛不反向连接插件。
- 依赖只有 httpx，AstrBot 已经自带。
- 论坛的 token：管理员在后台的 bot 页创建，bot 的 QQ 号填机器人自己的，范围选 `read`、`act`、`sync`、`auth`、`events`。
- AstrBot 这边：
  - 开了会话白名单的，要放行私聊，不然群友私聊 bot 登录会被拦下。
  - 群里的命令要带唤醒前缀（默认 `/`）或者 @bot，私聊不用。
- 本机时间要准：论坛拒收比服务器时间晚 10 分钟以上的同步数据。

## 3. 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `forum_url` | `https://bbs.mousebaoyan.cn` | 论坛地址 |
| `token` | 空 | 论坛的 bot token，界面上遮住显示 |
| `platform_id` | 空 | 接了多个 aiocqhttp 时指定用哪个，只有一个时留空 |
| `transfer_board` | `qa` | 转存的帖子发到哪个版块 |
| `lottery_groups` | 空 | 开奖结果发到哪些群，空的发到主群 |

同步哪些群在论坛后台关联，插件不另外配。同步频率、发消息的间隔都写成常量，见下面各节。

## 4. 结构

```text
NapCat ⇄ AstrBot（aiocqhttp）
           └ 鼠洞插件
               ├ 群消息、通知 → 命令、转存、回复同步、撤回、增量同步
               ├ 定时 → 全量同步、群资料
               └ 事件流 → QQ 提醒、开奖结果、个性签名
                     ⇅ REST、SSE（Bearer token，X-Act-As、X-Operator）
                  鼠洞论坛
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | AstrBot 入口：注册命令和监听，启动、停止后台任务 |
| `mousehole/forum.py` | 论坛接口：请求头、gzip，错误转成 `ForumError(code, message)` |
| `mousehole/qq.py` | 调用 NapCat；主动发的消息排队（第 11 节） |
| `mousehole/sync.py` | 成员同步 |
| `mousehole/relay.py` | 转存、回复同步、撤回 |
| `mousehole/events.py` | 事件流，以及它触发的提醒、开奖结果和个性签名 |
| `mousehole/commands.py` | 命令的解析和回复 |

论坛是唯一的数据源，插件几乎不存东西：数据目录（`data/plugin_data/astrbot_plugin_mousehole/`）里只有 `state.json`，记事件流的游标。谁在哪个群，取最近一次全量同步的名单，放在内存里。

## 5. 成员同步

按论坛总体设计 §6.3 推荐的，全量和增量一起用：

| 内容 | 做法 | 时机 |
| --- | --- | --- |
| 同步哪些群 | `GET /bot/groups`：后台关联且启用的群，主群在前 | 启动时、每轮全量前 |
| 完整成员名单 | `get_group_member_list`（`no_cache`）的结果原样转给 `PUT /bot/groups/{群号}/members`，带全部字段，gzip 压缩 | 启动后，之后每 10 分钟 |
| 群名、人数 | `get_group_info` → `PUT /bot/groups/{群号}/info` | 每小时 |
| 进群、退群、管理员、群名片、专属头衔 | QQ 通知转成增量，`PATCH /bot/groups/{群号}/members` | 收到通知时 |

- `observed_at`：全量用调用 NapCat 之前的时间，增量用通知里的 `time`。
- 通知按论坛接口 §4.2 的表转换；专属头衔是 `notify` 通知，`sub_type` 为 `title`。进群时再查一次 `get_group_member_info`，把昵称、群名片一起带上，账号一建好就有名字。
- bot 自己被踢（`kick_me`）或者群解散（`disband`）不推送，只记日志，由管理员在后台停用这个群。
- NapCat 发进群、退群、管理员变动的通知之前，会先刷新它的成员缓存，所以之后的全量不会用旧名单把增量盖回去。
- 全量被骤减保护拦下（`held`）时记一条警告。
- 全量总是带全部字段：两千人的名单压缩后约 100KB，十分钟一次的流量不值得再分哪次带哪些字段。

## 6. 登录和个人设置

私聊 bot：

| 发送 | 做什么 |
| --- | --- |
| `登录 482913`，或者只发 6 位口令 | `POST /bot/auth/code/confirm`，回复"已在 Chrome · macOS 登录鼠洞。不是你本人在登录的话，去设置页的登录设备让它下线：链接" |
| `登录链接` | `POST /bot/auth/links`，回复链接，10 分钟内有效，只能用一次 |

- 都以发送者的身份调用（`X-Act-As` 和 `X-Operator` 都是发送者）。论坛登录页上写的就是这两种说法。
- 在群里发 `/登录…` 只回一句"登录请私聊我"，口令和链接都不出现在群里。
- 个性签名：收到 `member.activated` 时用 `get_stranger_info` 查 `long_nick`，推给 `PUT /bot/users/qq:{QQ号}/bio`。
- "我的内容不给访客看"（论坛总体设计 §8.10）：`/鼠洞 隐藏`、`/鼠洞 公开`，群里、私聊都行，以发送者的身份 `PATCH /me` 改 `hide_from_guests`；没登录过论坛的也能用。

## 7. 群消息转存

在已同步的群里，引用一条消息发 `/转存`，或者 `/转存 标题`：

1. `get_msg` 取被引用那条的消息段，去掉 @bot 的。
2. `POST /threads`：
   - 发到 `transfer_board`，类型用版块默认的（保研问答是问答帖）。
   - 标题：命令里写了就用；没写就取消息文字的第一行，超过 40 个字截断；不到 4 个字时回复"这条消息太短，请写上标题：/转存 标题"。
   - `content.onebot` 是原消息段，`source` 是原消息。
   - `X-Act-As` 是原消息的发送者，`X-Operator` 是发命令的人，`Idempotency-Key` 是 `qq-{群号}-{消息 ID}-thread`。
3. 在群里引用原消息发回执：

   ```text
   已存到鼠洞：rank 30% 能冲夏令营吗
   https://bbs.mousebaoyan.cn/t/42
   引用回复这条消息，会同步进帖子
   ```

   发到先审后发的版块时，写"审核通过后公开"。回执用 `send_group_msg` 直接发，要拿到它的消息 ID（`context.send_message` 不返回）。
4. `PUT /bot/messages/group/{群号}/{回执的消息 ID}` 记下回执，之后引用它的回复才能找到帖子。

谁能转存由论坛判断：自己的消息谁都能转；转别人的，发命令的人得是论坛的版主或管理员（群主、群管理员同步过去就是），否则论坛返回 `operator_not_allowed`，插件回复"只能转存自己的消息，别人的请群管理员来"。已经转过的（`source_exists`）回复已有帖子的链接；其他失败（作者关了代发、被禁言等）直接回复论坛给的 `message`。

## 8. 回复同步

自动同步的群内容只有这一种：在群里引用转存回执的回复。其他消息都要有人 `/转存` 才会存到论坛。

1. 群消息里有引用，而且被引用的是 bot 自己发的（AstrBot 已经查出被引用消息的发送者），才去问论坛 `GET /bot/messages/group/{群号}/{被引用的消息 ID}`。
2. 是回执（`kind` 为 `notice`）就 `POST /threads/{帖子 ID}/posts`：`content.onebot` 是这条消息，去掉 @bot 的；`source` 是这条消息；`X-Act-As`、`X-Operator` 都是发送者；`Idempotency-Key` 是 `qq-{群号}-{消息 ID}-post`。
3. 成功了不在群里回复，免得刷屏；失败（论坛上被禁言、帖子锁了等）只记日志。
4. 处理完停止事件传播：AstrBot 把引用 bot 的消息当成唤醒，不停下来的话，开了大模型对话的 bot 会接着回一句。

引用回执就是本人想把这句话发到帖子里，所以 `X-Operator` 是本人，关了"允许代发"的人也能这样同步。

## 9. 撤回

群友撤回自己的消息（`group_recall` 里撤回的人就是发送者），而这条消息是论坛上某一层的来源时（`GET /bot/messages` 查得到），以本人的身份删掉那一层；是主楼就删帖子，帖子有人回复了论坛不让删，那就留着。管理员撤回别人的消息，插件不跟着处理。

## 10. 事件流

只订阅 `notification.created`、`member.activated`、`lottery.drawn` 三类。

- 先用 `GET /bot/events/batch` 把游标之后的事件补完，再连 `GET /bot/events`（SSE，带 `Last-Event-ID`）收新的。补发时看得到事件的时间，超过 12 小时的提醒和开奖结果不再发到 QQ、只往前推游标，免得插件停了一天，一开机就私聊一大堆过时的提醒。
- 每处理完一个事件，把游标存进 `state.json`。游标过期（`410 cursor_expired`）时从 `latest_id` 重新开始，记一条警告。第一次启动没有游标，从当前最新的事件开始。
- 断线后隔 1、2、5、10、30 秒重连，之后每 60 秒一次，每次都先补发。

**QQ 提醒**（`notification.created`）：把 `qq_text` 私聊发给 `user.qq`。

- 同一个人 5 分钟内最多一条，期间来的合并成一条发；一条里最多列 5 个提醒，再多的写"还有 N 条，去论坛看"和通知页的链接。
- 用 `send_private_msg` 发，带上这个人所在的一个群：是好友就直接私聊；不是好友，NapCat 走这个群的临时会话。临时会话可能被群设置或者 QQ 风控拦下，所以建议群友加 bot 为好友。
- 发不出去只记日志、不重试，提醒在论坛上都有。

**开奖结果**（`lottery.drawn`）：发到 `lottery_groups`，空的发到主群：

```text
【抽奖开奖】鼠群周年抽奖
一等奖：机械键盘 @鼠鼠
二等奖：鼠群周边 @阿柒 @夜猫子 @Rex
共 25 人参与
https://bbs.mousebaoyan.cn/t/42
```

一条最多 @ 20 个人，再多的只写名字；没人中的奖项写"无人中奖"。

## 11. 发消息的节奏

- 回复命令的消息（登录的回复、转存回执等）直接发。
- 主动发的（QQ 提醒、开奖结果）排队一条一条发，间隔 3–6 秒随机。AstrBot 里有维护者其他插件共用的操作协调器（`platform_manager._qq_automation_guard_v1`）时改走它，和那些插件一起排队，共用账号的发送间隔和掉线后的冷却。
- 读 NapCat 的：每个群每 10 分钟一次全量、每小时一次群资料，其余是收到通知、命令时的单次查询。

## 12. 命令

| 命令 | 在哪用 | 作用 |
| --- | --- | --- |
| `登录 口令`，或者只发 6 位口令 | 私聊 | 口令登录（第 6 节） |
| `登录链接` | 私聊 | 一次性登录链接 |
| `/鼠洞` | 群、私聊 | 帮助 |
| `/鼠洞 隐藏`、`/鼠洞 公开` | 群、私聊 | 我的内容不给访客看、恢复公开 |
| `/鼠洞 参与 帖子链接或编号` | 群、私聊 | 参与点按钮参与的抽奖，回复开奖时间和参与人数 |
| `/鼠洞 搜 关键词` | 群、私聊 | 搜论坛，回复前 3 个帖子的标题和链接；按访客的权限搜，不把仅成员版块的标题发到群里 |
| 引用一条消息发 `/转存`，或者 `/转存 标题` | 群 | 转存（第 7 节） |

- 只在已同步的群里响应，其他群里不理会；处理完都停止事件传播，不让大模型再回。
- 命令都以发送者的身份调用论坛。论坛返回的错误 `message` 本来就是给人看的，直接回复；几种常见的换成更具体的说法：

  | 错误码 | 回复 |
  | --- | --- |
  | `unknown_member` | 论坛还没同步到你，进群后稍等几分钟再试 |
  | `member_frozen` | 你已经不在鼠群里了 |
  | `login_code_invalid` | 口令不对或者过期了，刷新网页拿个新的 |

- 论坛连不上时回复"鼠洞暂时连不上，稍后再试"。

## 14. 测试

- 单元测试（pytest）：用假的论坛（httpx 的 `MockTransport`）、假的 NapCat 和 AstrBot 事件，测通知转增量、全量、转存（标题、幂等键、错误回复）、回复同步、撤回、事件流的补发和游标、提醒的合并、开奖消息、命令解析。
- 本地联调：本机跑论坛（`pnpm dev`，`pnpm mock-bot setup` 建 token）、AstrBot 和一个模拟 NapCat 的脚本：脚本用反向 WebSocket 连上 AstrBot，发群消息和通知，应答 OneBot 接口，把上面的流程都走一遍。
- 真 QQ 号：维护者在测试群里验证。
- CI：ubuntu 和 windows、Python 3.12 和 3.13，跑 pytest 和 ruff。

## 15. 待定事项

- 回复同步的范围：只同步引用回执的回复（现在的写法），还是引用帖子里任何一条群消息（原问题、已经同步的回复）的回复也同步。后者能把整串讨论都存下来，但群友不一定知道自己的话会发到论坛。
- 好友申请：要不要自动通过群友加 bot 好友的申请，让 QQ 提醒走好友私聊，不依赖临时会话。
