# 鼠洞插件 · 设计

> 状态：草案。第 6、7、10、11 节已经定了，可以照着实现；第 8 节（自动收录问答）和第 9 节（通知）还在讨论，待定的问题列在第 14 节。论坛一侧见鼠洞仓库的[总体设计](https://github.com/mousebaoyan/mousehole/blob/main/docs/design.md)和[接口](https://github.com/mousebaoyan/mousehole/blob/main/docs/api.md)；本文只写插件自己的部分，接口细节以论坛的文档为准。

## 1. 目标

AstrBot 插件，把鼠群的 QQ 群和鼠洞论坛连起来（论坛总体设计 §14 M9）。群友几乎感觉不到它，它只做这几件事：

- 登录入口：私聊 bot 登录论坛。
- 群成员同步到论坛。
- 自动收录：群里值得留下来的问答，自动存成论坛的帖子和回复（第 8 节）。
- 通知：开奖结果发到群里；论坛的提醒怎么送到本人，见第 9 节。

不做：
- 群里的命令：转存、"不给访客看"、参与抽奖、搜索，都到论坛上操作。
- 收录后发回执。
- 自动通过好友申请。
- LLM 审核。
- 二期的播报、群公告和精华同步。

## 2. 防风控

QQ 的风控会识别"像机器人"的账号，插件尽量让 bot 的操作和真人没有区别：

- 群消息和通知只被动接收。
- 读 NapCat 只读它的缓存，不让它为插件额外去 QQ 服务器拉数据。
- 不主动私聊别人，私聊只回复本人发来的消息（登录）。
- 主动发到群里的只有开奖结果。
- 发出的消息尽量不带链接，必须带的只有登录链接和开奖结果。

插件让 NapCat 做的事只有这些：

| 操作 | 会不会请求 QQ 服务器 | 什么时候 |
| --- | --- | --- |
| `get_group_member_list`、`get_group_info`，都不带 `no_cache` | 不会，读 NapCat 的缓存 | 每小时；有人进群时 |
| `get_stranger_info` 查个性签名 | 会 | 有人第一次登录论坛时 |
| 私聊回复登录 | 会 | 本人私聊 bot 时 |
| 发开奖结果 | 会 | 开奖时 |

- `get_group_member_list` 带 `no_cache: true` 时，NapCat 会在后台重新拉名单，却仍然先返回旧的缓存，所以插件从来不带。
- `get_group_member_info` 默认就强制刷新，还会多查一次这个人的资料，所以插件不用它。

开奖结果排队发，间隔 3–6 秒随机。AstrBot 里有维护者其他插件共用的操作协调器（`platform_manager._qq_automation_guard_v1`）时改走它，和那些插件一起排队，共用账号的发送间隔和掉线后的冷却。

## 3. 运行环境

- AstrBot 4.26.2 以上、5.0 以下，Python 3.12 以上（这些版本的 AstrBot 本身就要求 3.12）。通过 aiocqhttp 反向 WebSocket 接 NapCat，接口按 NapCat 4.18 核对；只支持 aiocqhttp。
- 插件主动连接论坛（REST 和事件流），所在的机器能访问外网就行，论坛不反向连接插件。
- 自动收录还要：
  - 本机的 [OneJev](https://github.com/OmniJev/OneJev) 服务，可以和 message_guard 插件共用一个；
  - AstrBot 里配好的一个大模型。
- 依赖只有 httpx，AstrBot 已经自带。
- 论坛的 token：管理员在后台的 bot 页创建，bot 的 QQ 号填机器人自己的，范围选 `read`、`act`、`sync`、`auth`、`events`。
- AstrBot 开了会话白名单的，要放行已同步的群和私聊。
- 本机时间要准：论坛拒收比服务器时间晚 10 分钟以上的同步数据。

## 4. 配置

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `forum_url` | `https://bbs.mousebaoyan.cn` | 论坛地址 |
| `token` | 空 | 论坛的 bot token，界面上遮住显示 |
| `platform_id` | 空 | 接了多个 aiocqhttp 时指定用哪个，只有一个时留空 |
| `lottery_groups` | 空 | 开奖结果发到哪些群，空的发到主群 |
| `onejev_url` | `http://127.0.0.1:8000` | OneJev 服务的根地址 |
| `llm_provider` | 空 | 给收录的帖子把关、起标题的模型，从 AstrBot 配好的里选；空的用 AstrBot 的默认模型 |
| `archive_board` | 待定 | 收录的帖子发到哪个版块 |
| `archive_trial` | 开 | 试运行：只记下本来会发的帖子，不发（第 8.4 节） |

同步哪些群在论坛后台关联，插件不另外配；收录也只在这些群里做。频率、门槛、间隔都写成常量，见下面各节。

## 5. 结构

```text
NapCat ⇄ AstrBot（aiocqhttp）
           └ 鼠洞插件
               ├ 群消息 → 自动收录、撤回
               ├ 私聊 → 登录
               ├ 群通知 → 成员增量
               ├ 每小时 → 成员全量、群资料
               └ 事件流 → 开奖结果、个性签名
                     ⇅ REST、SSE（Bearer token，X-Act-As）
                  鼠洞论坛
自动收录另外调用本机的 OneJev 和 AstrBot 里的大模型
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | AstrBot 入口：注册监听，启动、停止后台任务 |
| `mousehole/forum.py` | 论坛接口：请求头、gzip，错误转成 `ForumError(code, message)` |
| `mousehole/qq.py` | 调用 NapCat；主动发的消息排队 |
| `mousehole/sync.py` | 成员同步 |
| `mousehole/login.py` | 私聊登录 |
| `mousehole/archive.py` | 自动收录：跟进问题，调用 OneJev 和大模型，发帖 |
| `mousehole/events.py` | 事件流，以及它触发的开奖结果和个性签名 |

论坛是唯一的数据源，插件几乎不存东西。数据目录（`data/plugin_data/astrbot_plugin_mousehole/`）里只有两个文件：
- `state.json`：事件流的游标；
- `trial.jsonl`：试运行的记录。

谁在哪个群、跟进中的问题都只放在内存里。

## 6. 成员同步

| 内容 | 做法 | 时机 |
| --- | --- | --- |
| 同步哪些群 | `GET /bot/groups`：后台关联且启用的群，主群在前 | 启动时、每小时 |
| 完整成员名单 | `get_group_member_list` 的结果原样转给 `PUT /bot/groups/{群号}/members`，带全部字段，gzip 压缩 | 启动后，之后每小时 |
| 群名、人数 | `get_group_info` → `PUT /bot/groups/{群号}/info` | 和全量一起 |
| 进群、退群、管理员、群名片、专属头衔 | QQ 通知转成增量，`PATCH /bot/groups/{群号}/members` | 收到通知时 |

NapCat 自己维护成员缓存，插件只读它（第 2 节）。不管有没有插件，NapCat 都会：
- 启动时拉一遍所有群的名单；
- 有人进群、退群、管理员变动时，先重新拉这个群的名单再发通知；
- 有人改了群名片，等他下次发言时更新。

所以缓存够新，全量每小时读一次就够了。

- 进群时，从缓存的名单里取出这个人的记录一起推，账号一建好就有名字。
- 缓存里的最后发言时间只在 NapCat 重新拉名单时更新。插件本来就在看群消息，全量时用看到的最近发言时间，替换缓存里更早的。
- `observed_at`：全量用读缓存的时间，增量用通知里的 `time`。
- 通知按论坛接口 §4.2 的表转换；专属头衔是 `notify` 通知，`sub_type` 为 `title`。
- bot 自己被踢（`kick_me`）或者群解散（`disband`）不推送，只记日志，由管理员在后台停用这个群。
- 全量被骤减保护拦下（`held`）时记一条警告。

头像不经过插件，论坛每天自己从 QQ 头像接口拉。个性签名由插件推：收到 `member.activated` 时，用 `get_stranger_info` 查 `long_nick`，推给 `PUT /bot/users/qq:{QQ号}/bio`。

## 7. 登录

私聊 bot，以"登录"开头的消息：

| 发送 | 做什么 |
| --- | --- |
| `登录`、`登录链接` | `POST /bot/auth/links`，回复一次性登录链接，10 分钟内有效，只能用一次 |
| `登录 482913`，或者只发 6 位口令 | `POST /bot/auth/code/confirm`，回复"已在 Chrome · macOS 登录鼠洞。不是你本人在登录的话，到鼠洞设置页的登录设备里让它下线。" |

- "登录"后面跟 6 位数字就是口令，其他都发链接。
- 以发送者的身份调用（`X-Act-As` 和 `X-Operator` 都是发送者）。
- 群里 @bot 说"登录…"时，只回一句"登录请私聊我"。不 @ 的群消息不理会，群友聊天里说到"登录"很常见。
- 论坛返回的错误 `message` 本来就是给人看的，直接回复。几种常见的换成更具体的说法：

  | 错误码 | 回复 |
  | --- | --- |
  | `unknown_member` | 论坛还没同步到你，进群后稍等几分钟再试 |
  | `member_frozen` | 你已经不在鼠群里了 |
  | `login_code_invalid` | 口令不对或者过期了，刷新网页拿个新的 |

- 论坛连不上时回复"鼠洞暂时连不上，稍后再试"。
- 处理完停止事件传播，不让大模型再回。

## 8. 自动收录问答（讨论中）

群里值得留下来的保研问答，自动存成论坛的帖子：
- 提问是主楼，群友的相关回答是回复；
- 都记在本人名下，论坛上标"来自群聊"；
- bot 不在群里说话，群友察觉不到。

先只收问答。经验分享、通知（入营名单、学校公告）以后再加。

### 8.1 三层判断

越往后越贵，经过的消息越少：

| 层 | 花费 | 做什么 |
| --- | --- | --- |
| 规则 | 无 | 只看已同步的群里成员发的消息。去掉 bot 自己的、命令、只有表情或图片的，以及太短的：提问不到 10 个字，回复不到 4 个字 |
| OneJev | 本机算力，不花 token | 认出提问；判断新消息在回答哪个问题 |
| 大模型 | token，每个帖子一次 | 发帖前最后把关，起标题 |

**OneJev**：只做选择题，返回各个选项的概率，不生成文字。
- 每个群把新消息攒 1 分钟，再发一次 `/v1/systemone` 请求。
- 前文、跟进中的问题和新消息都放在 `state` 里，同一次请求里的几个判断共用这段前文，只算一次。
- 有问句特征的新消息（问号，或者"吗""怎么""有没有""求问"这类说法），问 `noul`：是不是别人能回答、以后的人也可能会查的保研提问。
- 有跟进中的问题时，每条新消息问 `choice`：在回答或讨论哪个问题，还是都不是。附和、道谢、闲聊算都不是。
- 引用了跟进中的问题或者已收录消息的，直接算相关，不问模型。
- 作者在 `state` 里写成 U1、U2，不给模型看 QQ 号和群名片。

**大模型**：问题第一次有别人回答时，把问题和已有的回答发给 `llm_provider`，让它回 `{"keep": true, "title": "……"}`：值不值得存，标题不超过 30 个字。
- 值得存就发帖。
- 不值得就不再跟进这个问题。
- 一次大约一两千 token。

### 8.2 发帖

- 主楼：`POST /threads`。
  - 版块是 `archive_board`，类型用版块默认的，标题用大模型起的。
  - `content.onebot` 是原消息段，`source` 是原消息，`X-Act-As` 是提问的人。
- 回复：`POST /threads/{帖子 ID}/posts`，`X-Act-As` 是回答的人。原消息引用了帖子里某一条的，论坛自动记成回复那一层。
- 都不带 `X-Operator`，因为自动收录没有操作人。
  - 关了"允许代发"的人，论坛会拒绝（`403 proxy_disabled`），插件就跳过这条。
  - 提问的人关了，整个问题都不存。
- `Idempotency-Key` 是 `qq-{群号}-{消息 ID}-thread` 或 `qq-{群号}-{消息 ID}-post`。
- 图片由论坛在发帖时转存。问题等到有人回答才发帖，一般赶得上图片链接过期之前。

### 8.3 跟进多久

- 问题 2 小时内没人回答，就放弃。
- 离最后一条相关消息 30 分钟以内的新消息，都还要判断是不是相关。
- 超过 30 分钟，只收引用了已收录消息的回复，用 `GET /bot/messages` 问论坛这条属于哪个帖子。
- 每个群同时最多跟进 5 个问题，多了就放弃最早的。
- 跟进中的问题只在内存里，插件重启就丢了；已经发出的帖子，靠引用还能接着收。

### 8.4 试运行

`archive_trial` 开着时照常判断，只是不发帖：把本来会发的帖子记进数据目录的 `trial.jsonl`，包括标题、每条消息和各层的判断结果。维护者看过、调好门槛再关掉。

### 8.5 不做

- 合并转发、文件和语音，按论坛的规则显示成"[聊天记录]"等，不展开。
- 以前问过的同一个问题，暂不并进旧帖子。

## 9. 通知（讨论中）

**开奖结果**（`lottery.drawn`，已定）：发到 `lottery_groups`，空的发到主群：

```text
【抽奖开奖】鼠群周年抽奖
一等奖：机械键盘 @鼠鼠
二等奖：鼠群周边 @阿柒 @夜猫子 @Rex
共 25 人参与
https://bbs.mousebaoyan.cn/t/42
```

- 一条最多 @ 20 个人，再多的只写名字。
- 没人中的奖项写"无人中奖"。

**论坛的提醒怎么送到本人**：原来的做法是 bot 私聊本人。bot 不加好友，私聊就都要走临时会话。主动给很多陌生人发临时会话，是很典型的机器人特征。可选的做法：

| 做法 | 风控 | 送达 | 要改的 |
| --- | --- | --- | --- |
| A. 论坛发邮件到 `QQ号@qq.com`，按人合并 | 和 bot 无关 | QQ 邮箱提醒开着的话，在 QQ 里就能看到 | 论坛：通知渠道"QQ 提醒"换成"邮件"，复用登录验证码用的 SMTP；插件不用做 |
| B. 只私聊最近私聊过 bot 的人，比如经 bot 登录过的 | 低：对方先开的口 | 只覆盖这部分人 | 插件记下谁私聊过 |
| C. 每天在群里发一条汇总，@ 有新提醒的人 | 低 | 一天一次，不及时；群里多一条消息 | 插件 |
| D. 只在论坛站内提醒 | 无 | 要本人打开论坛才看得到 | 论坛去掉"QQ 提醒" |

倾向 A：bot 完全不主动私聊。

## 10. 撤回

群友撤回自己的消息，而这条消息是论坛上某一层的来源时，以本人的身份删掉那一层：
- 撤回的人就是发送者，从 `group_recall` 里看；
- 是不是来源，用 `GET /bot/messages` 查；
- 是主楼就删整个帖子；帖子已经有人回复的，论坛不让删，就留着。

管理员撤回别人的消息，插件不跟着处理。

## 11. 事件流

订阅 `member.activated`、`lottery.drawn`；第 9 节选了 B 或 C 的话，再加 `notification.created`。

- 先用 `GET /bot/events/batch` 把游标之后的事件补完，再连 `GET /bot/events`（SSE，带 `Last-Event-ID`）收新的。
- 补发时看得到事件的时间。超过 12 小时的开奖不再发到群里，只往前推游标，免得插件停了一天，一开机就发一堆过时的结果。
- 每处理完一个事件，把游标存进 `state.json`。
- 游标过期（`410 cursor_expired`）时从 `latest_id` 重新开始，记一条警告。
- 第一次启动没有游标，从当前最新的事件开始。
- 断线后隔 1、2、5、10、30 秒重连，之后每 60 秒一次，每次都先补发。
